# Инструкция для AI-сессии (агент)

Этот файл читают все, кто работает с репозиторием `tenkrol/agent`: человек, агент, любой
инструмент.

## Сначала прочитать
1. `openspec/project.md` — что за проект, серверы, ограничения.
2. `openspec/conventions.md` — язык, тесты, деплой, DoD, секреты, запреты.
3. `openspec/README.md` — ритуал OpenSpec (шаги, статусы, что значит «готово»).
4. `openspec/changes/PLA-<номер>/` — что уже в работе (спека идёт до кода).
5. `openspec/changes/archive/README.md` — что уже сделано и под каким номером.
6. `HANDOFF.md` — состояние на сейчас.

## Главное правило
**Код меняется только в рамках папки изменения** `openspec/changes/PLA-<номер>/` со
спекой и задачами. Сначала спека и одобрение владельца — потом код.

## Номер изменения
Папки называются `PLA-<номер>`: сквозной номер по порядку, без дат и без слагов.
Новый номер = **последний номер в `openspec/changes/archive/` + 1**, с учётом активных
папок в `openspec/changes/`. На 2026-10-17 заняты `PLA-1 … PLA-17` (активные —
`PLA-13 … PLA-17`), следующий свободный — **PLA-18**. Повторять номер нельзя: проверка
`bash tools/spec-check.sh` сообщит, что номер уже занят, и проверит остальную структуру
(proposal, design, tasks, дельта спеки, имя папки).

## Git: работа не закрыта без коммита и пуша
Каждая сессия и каждый инструмент ОБЯЗАНЫ закоммитить свою работу и отправить её в
`origin/main`. Незакоммиченное изменение считается потерянным: его не видит ни владелец,
ни другая сессия, ни `git pull` на другой машине.

Порядок в конце работы (обязателен):
1. `bash tools/spec-check.sh` — структура изменений;
2. `node --test --test-force-exit test/*.test.mjs` — тесты;
3. `git add -A && git commit -m "…причина изменения…"`;
4. `git push origin main`;
5. `bash tools/git-check.sh` — подтверждает, что дерево чистое и всё отправлено.

Проверка `git-check` не пропускает: незакоммиченные файлы, неотправленные коммиты,
работу без апстрима. Единственное исключение из «дерево чистое» — `.DS_Store`.
Если коммит делать нельзя (например, нет доступа к origin), сессия обязана прямо сказать
об этом владельцу, а не молча оставить изменения незакоммиченными.

## Обязанности
- Спеки и комментарии в коде — по-русски.
- Перед деплоем — полный локальный прогон: `node --test --test-force-exit test/*.test.mjs`.
- Деплой только через `bash deploy/install-remote.sh` (новый релиз + симлинк, откат —
  переключить симлинк обратно).
- Обновить `HANDOFF.md` в конце сессии.
- Закрыть изменение: влить дельту в `openspec/specs/`, перенести папку в
  `changes/archive/`.
- Закоммитить и запушить результат: `git add -A && git commit && git push origin main`,
  затем `bash tools/git-check.sh`.

## Секреты
Только в `secrets/agent.env.enc` (шифртекст), пароль вне репозитория; расшифровка
`bash tools/secrets.sh decrypt`; имена — в `secrets/keys.md`. Значений в репозитории,
в чате и в логах быть не должно.

## Запреты
- Не перезаписывать `/etc/agent/agent.env` установщиком.
- Не включать `MemoryDenyWriteExecute` и не менять `ProtectControlGroups=false`.
- Не писать руками в файлы состояния агента (`state/observations.jsonl`, `state/alerts.jsonl`,
  `state/alerts.json`, `state/tasks.jsonl`).
- Не перезагружать серверы без разрешения владельца: на испанском сервере живёт
  VPN-инфраструктура, её не трогаем.
