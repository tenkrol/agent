# Изменение: вынести настройки агента в домен config

## Зачем
`src/config.mjs` — 489 строк, и в нём перемешаны три вещи: чтение окружения, валидация
значений и знание о том, какие ключи являются секретами. Из-за этого `process.env`
читается ещё и в других местах, а тест «а что если лимит отрицательный» требует собирать
весь конфиг целиком.

## Что меняется
Появляется домен `src/config/`: единственное место, где читается окружение и где значения
валидируются. Наружу — один публичный API (`loadConfig`, `ConfigError`, `secretsOf`) и
готовый объект настроек. Другие домены получают настройки только из него.

## Чего не делаем
- Не меняем ни одну переменную, её значение по умолчанию и границы — поведение идентично.
- Не трогаем `secrets` (шифртекст и реестр имён) — это следующий шаг очереди.
- Не меняем формат сообщений об ошибках, кроме путей в стеке.

## Как проверяем
- Полный прогон тестов зелёный, включая существующие тесты конфига.
- Новый сторожевой тест: `process.env` читается только внутри `src/config/`.
- Живой старт сервиса после деплоя и одна задача через мост.
