# Изменение: вынести секреты в домен secrets

## Зачем
Шифрование секретов живёт в `tools/secrets.mjs` как скрипт с побочными эффектами: логика
шифрования, разбор конверта и работа с файлами перемешаны с `process.argv`, а пароль
читается из окружения прямо в точке использования. Из-за этого нельзя ни протестировать
крипто без запуска процесса, ни запретить другим доменам трогать файл секретов.

## Что меняется
Появляется домен `src/secrets/`: чистые функции шифрования (`crypto.mjs`), работа с файлами
(`index.mjs`) и CLI (`cli.mjs`). `tools/secrets.sh` и `tools/secrets.mjs` остаются точками
входа с прежним интерфейсом (`encrypt|decrypt|check`) и становятся тонкими обёртками.

## Чего не делаем
- Не меняем формат конверта (v=1, AES-256-GCM, scrypt) — старые файлы читаются.
- Не меняем способ передачи пароля: `SECRETS_PASSPHRASE` в окружении, не в argv.
- Не перекладываем сам файл `secrets/agent.env.enc`.

## Как проверяем
- Тесты домена: roundtrip encrypt→decrypt, неверный пароль, повреждённый конверт, `check`
  печатает только имена.
- Сторожевые тесты: файл шифртекста читается только в `src/secrets/`; реестр `secrets/keys.md`
  не содержит значений.
- Живой прогон: `bash tools/secrets.sh check` на расшифровываемом файле.
