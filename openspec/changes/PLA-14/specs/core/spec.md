# Дельта для домена core

## ADDED Requirements

### Requirement: Задача из ассистента отвечает по своему маршруту
Задача с маршрутом ДОЛЖНА направлять вопрос, варианты и результат в исходный разговор, а не
в личный чат агента. Личный чат остаётся для личных задач; состояние отмены ассистент
читает по контракту.

#### Scenario: Уточнение из исходного разговора
- GIVEN задача пришла из разговора ассистента
- WHEN агенту нужен ответ владельца
- THEN вопрос уходит по сохранённому маршруту
- AND ответ владельца продолжает ту же задачу и сессию

#### Scenario: Личная задача
- GIVEN у задачи нет маршрута
- WHEN агенту нужен ответ
- THEN вопрос уходит в чат агента, как раньше

#### Scenario: Отмена
- GIVEN задачу отменили через контракт
- WHEN ассистент запрашивает состояние
- THEN он видит `cancelled` в `GET /v1/tasks/:id`
- AND отдельного пользовательского сообщения об отмене не создаётся

### Requirement: Воркер доставки в ядре
Ядро ДОЛЖНО запускать и останавливать воркер доставки, не смешивая её с выполнением задач.

#### Scenario: Запуск и остановка сервиса
- GIVEN сервис стартует
- WHEN есть незавершённые доставки
- THEN воркер подхватывает их и повторяет по расписанию
- AND остановка сервиса прекращает воркер без потери записей

#### Scenario: Доставка не запускает задачу
- GIVEN доставка повторяется
- WHEN воркер отправляет событие
- THEN исполнитель задачи не запускается
- AND состояние выполнения не меняется

#### Scenario: Служебное событие
- GIVEN агент предлагает ассистенту сохранить рабочий факт
- WHEN событие уходит по контракту
- THEN сообщение пользователю не создаётся
- AND состояние задачи не меняется

### Requirement: Ревизия результата
Ядро ДОЛЖНО создавать новую версию задачи по запросу владельца, используя прошлый
результат как входной материал и сохраняя связь с исходной задачей.

#### Scenario: Доработка документа
- GIVEN у задачи есть готовый документ
- WHEN владелец просит изменить раздел
- THEN создаётся задача-ревизия с номером версии больше прежнего
- AND в промпт попадает прошлый результат и просьба изменить только запрошенное
- AND прежняя версия остаётся доступной

#### Scenario: Прошлый файл недоступен
- GIVEN файл прошлой версии уже удалён по сроку хранения
- WHEN создаётся ревизия
- THEN задача создаётся
- AND владелец явно получает предупреждение, что прежний файл недоступен

### Requirement: Ручной повтор доставки
Ядро ДОЛЖНО позволять владельцу повторить неуспешную доставку, не выполняя задачу заново.

#### Scenario: Повтор после исчерпания попыток
- GIVEN доставка помечена неуспешной
- WHEN владелец вызывает повтор
- THEN события задачи снова ставятся в очередь с прежними идентификаторами
- AND исполнитель не запускается

#### Scenario: Аварийное уведомление
- GIVEN доставка события ассистенту окончательно не удалась
- WHEN все попытки исчерпаны
- THEN владелец получает уведомление в личном чате агента
- AND задача не выполняется повторно
