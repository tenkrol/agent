# Техническое решение

## Как устроено сейчас
- `src/storage/memory.mjs`: `memory.json` с `{version: 1, facts: [{id, text, createdAt,
  source}]}`; предел 120 фактов по 300 символов; `add`, `forget`, `clear`, `render`
  (в промпт уходит весь список до 3000 символов), `ingest` фактов из `memory.md`.
- `execution/prompt.mjs` безусловно вставляет `memory.render()` в текст задачи.
- Команды: `/memory` (список), `/remember <текст>`, `/forget <номер|id|фрагмент>`.
- Секреты: значения не должны попадать в промпт/логи; сейчас есть только редактирование
  логов (`ops/logger.mjs`), проверок в памяти и отчёте нет.

## Предлагаемое решение

### Схема памяти версии 2
```json
{
  "version": 2,
  "facts": [
    {
      "id": "f...",
      "text": "часовой пояс владельца — Europe/Moscow",
      "kind": "preference",
      "subject": "timezone",
      "scope": { "type": "global", "value": null },
      "source": { "type": "owner", "ref": "message:433296567:12345", "owner": "agent" },
      "createdAt": 1760000000000,
      "validFrom": 1760000000000,
      "validUntil": null,
      "status": "active",
      "supersedes": "f-old",
      "supersededBy": null
    }
  ]
}
```
- `kind`: `preference` (постоянное предпочтение), `temporary` (временное сведение с
  `validUntil`), `task` (контекст задачи; `scope.type = "task"`, `scope.value = taskId`).
- `source.type`: `owner` (сказал владелец), `agent` (вывел агент из своей работы),
  `assistant` (передал ассистент как владелец личных фактов).
- `scope.type`: `global`, `chat`, `task`.
- `status`: `active`, `superseded`, `expired`.
- Замена: новый факт с тем же `subject` + `scope` в статусе `active` переводит прежний в
  `superseded` и связывает `supersedes`/`supersededBy`. Прежний факт остаётся в истории.
- `validUntil` в прошлом → `expired` при загрузке/выборке; в промпт не попадает, в истории
  виден.
- Пределы: 120 активных фактов, 300 символов на факт (как раньше), история — до
  `MEMORY_HISTORY_MAX` (500), обрезка старых записей по времени.

### Владельцы данных
- Ассистент — основной владелец личных фактов. Агент НЕ сохраняет личные факты,
  переданные ассистентом: они приходят в запросе задачи (`context.facts`) и используются
  только для этой задачи.
- Агент хранит рабочий контекст задач и предпочтения, явно сообщённые ему владельцем.
- Рабочие факты, которые агент хочет сохранить навсегда, уходят событием
  `memory_proposal` (PLA-14); решение принимает ассистент. Агент не пишет личную память
  молча.
- `memory.md` из рабочей папки остаётся источником рабочих фактов агента, но строка может
  содержать `subject`: `- [timezone] Europe/Moscow`; такая запись заменяет прежнюю с тем же
  `subject`. Без `subject` — обычное добавление.

### Выбор памяти для задачи
`memory.renderForTask({ text, scope, budget = MEMORY_CONTEXT_CHARS })`:
- берёт только `active` и неистёкшие факты;
- `scope.global` и `scope.chat` (этот чат), `scope.task` — только для своей задачи;
- отбирает по простому соответствию теме задачи (совпадение значимых слов) и свежести,
  затем добирает до бюджета; задача без темы получает только глобальные предпочтения;
- жёсткий предел `MEMORY_CONTEXT_CHARS` (1500) — меньше прежних 3000: контекст задачи и так
  дорог, а лишние факты ухудшают результат;
- контекст задачи (`kind: task`) удаляется при закрытии задачи с учётом срока хранения.

### Исправление устаревшего факта
- Владелец явно сообщает новое значение: команда `/memory set <subject> <текст>` или
  `memory.md` со `subject`, либо ассистент присылает факт с `subject` через согласованный
  интерфейс.
- Новая запись становится `active`, прежняя — `superseded`; в промпт попадает только
  активная; `/memory history <subject>` показывает обе с датами и источником.
- Удаление (`/forget`) остаётся, но не является способом «исправления»: история сохраняется
  до `/memory purge` (явная очистка, с подтверждением).

### Защита от секретов
- `src/secrets/guard.mjs`: `containsSecret(text, secretValues)` — проверка по известным
  значениям окружения и по шаблонам ключей (`sk-…`, `bot<digits>:…`, длинные base64/hex);
  `redact(text, secretValues)`.
- Память: `add`/`apply` отклоняет факт, содержащий значение секрета (пишет в лог только имя
  ключа, без значения).
- Промпт: перед сборкой проверяется; при утечке — факт исключается и пишется предупреждение.
- Отчёт: перед отправкой текст и имена файлов проверяются; найденное значение вырезается,
  владельцу уходит предупреждение «в отчёте был секрет, вырезан».
- Журнал памяти и логи: значения не пишутся; логгер уже редактирует известные секреты.

### Контракт с ассистентом (дополнение к PLA-14)
- `POST /v1/tasks` может содержать `context.facts: [{ text, subject?, validUntil? }]` —
  факты ассистента для этой задачи; агент их не сохраняет.
- Событие `memory_proposal`: `{ type: "memory_proposal", proposal: { text, subject?, kind,
  scope } }` — агент предлагает рабочую запись, ассистент решает.
- `GET /v1/memory/context?text=…` не вводится: отбор делает ассистент, агенту достаточно
  `context.facts`.

### Команды
- `/memory` — активная память по видам и областям, с датами и источником;
- `/memory history [subject]` — история, включая заменённые и истёкшие;
- `/memory set <subject> <текст>` — явное исправление (замена);
- `/remember [--until YYYY-MM-DD] [--kind temporary] <текст>` — добавление;
- `/forget <номер|id|фрагмент>` — забыть факт (история остаётся);
- `/memory purge` — полная очистка с подтверждением.

### Миграция и откат
- При загрузке `version: 1`: каждый факт становится `kind: preference`, `scope: global`,
  `status: active`, `subject: null`, `source.type: owner` (или `agent` для фактов из
  `memory.md` — по прежнему полю). Перед миграцией — копия `memory.json.v1.bak`.
- Откат: предыдущий релиз не поймёт версию 2 и отложит файл в `.corrupt-…`; поэтому откат
  выполняется с восстановлением `memory.json.v1.bak`. Это документируется в HANDOFF.
- `memory.json` остаётся совместимым по расположению и правам.

## Влияние
- Меняются `src/storage/memory.mjs`, `src/execution/prompt.mjs`, `src/core/bot.mjs`
  (команды, проверка отчёта), `src/secrets/guard.mjs`, `src/bot-link` (контекст и событие),
  `src/config/`, тесты, README.
- Промпт становится короче: меньше токенов на задачу, но выше требования к отбору —
  закрывается тестами релевантности.
- Риск: потеря фактов при миграции — закрывается бэкапом и тестом миграции.
- Риск: секрет уже был в памяти до обновления — при загрузке значения не показываются, а
  при первой записи факт с секретом исключается; ручная проверка `/memory` в живом прогоне.

## Альтернативы
- Оставить плоский список и добавить только `validUntil` — не решает владение, историю и
  исправление; отвергнуто.
- Векторный поиск по памяти — внешние зависимости и непрозрачность; отвергнуто.
- Хранить личные факты в агенте и синхронизировать с ассистентом — два владельца и
  конфликты; отвергнуто в пользу «ассистент владеет, агент использует на задачу».
- Автоматически заменять факты моделью — непредсказуемо и дорого; отвергнуто в пользу
  явного `subject` и команд.
