# Дельта для домена storage

## ADDED Requirements

### Requirement: Виды памяти различаются
Хранилище ДОЛЖНО различать постоянные предпочтения, временные сведения и контекст задачи.
Долговременная запись ДОЛЖНА иметь источник, дату, область применения и при необходимости
срок актуальности. Хранилище агента содержит только его собственную память: рабочий
контекст задач и предпочтения, явно сообщённые владельцем агенту; личные факты ассистента в
нём НЕ хранятся.

#### Scenario: Временное сведение
- GIVEN сохраняется временный факт со сроком
- WHEN срок истёк
- THEN факт не считается действующим
- AND остаётся в истории

#### Scenario: Контекст задачи
- GIVEN факт относится к задаче
- WHEN задача закрыта и срок хранения истёк
- THEN факт не попадает в другие задачи
- AND удаляется по правилам хранения

#### Scenario: Факт ассистента
- GIVEN ассистент передал личный факт для задачи
- WHEN задача завершена
- THEN факт не записан в `memory.json`
- AND другие задачи его не видят

### Requirement: Исправление устаревшего факта
Новый факт с тем же предметом и областью ДОЛЖЕН становиться действующим, а прежний —
переводиться в историю. Прежний факт НЕ ДОЛЖЕН использоваться как актуальный, изменение
ДОЛЖНО быть доступно для просмотра.

#### Scenario: Новый часовой пояс
- GIVEN в памяти сохранён часовой пояс владельца
- WHEN владелец явно сообщает новый
- THEN новая запись становится действующей
- AND предыдущая не используется как актуальная
- AND изменение доступно для просмотра

### Requirement: История памяти сохраняется
Хранилище ДОЛЖНО сохранять заменённые и истёкшие факты для просмотра и объяснения
поведения, не используя их в задачах. Предел истории — `MEMORY_HISTORY_MAX`.

#### Scenario: Просмотр истории
- GIVEN факт был заменён
- WHEN владелец запрашивает историю
- THEN видны новый и прежний факты с датами и источником
- AND в промпт попадает только действующий

### Requirement: Отбор памяти для задачи
Хранилище ДОЛЖНО отбирать для задачи только действующие, неистёкшие и относящиеся к ней
факты в пределах бюджета `MEMORY_CONTEXT_CHARS` и предела `MEMORY_MAX_FACTS`.

#### Scenario: Чужая область
- GIVEN факт относится к другому чату или задаче
- WHEN собирается память для текущей задачи
- THEN факт не попадает в результат
- AND бюджет соблюдается

### Requirement: Секреты не попадают в память и не показываются
Хранилище НЕ ДОЛЖНО сохранять значения секретов. Попытка записи такого факта отклоняется,
в журнал попадает только имя ключа, без значения. При выдаче памяти (список и история)
значения секретов ДОЛЖНЫ вырезаться или факт скрываться, даже если он оказался в файле до
обновления. Проверка выполняется связанным guard-портом домена `secrets`; порт создаётся в
точке сборки из `config`, значения секретов в хранилище не передаются, шифртекст и
окружение хранилище не читает.

#### Scenario: Факт с ключом
- GIVEN факт содержит значение известного секрета
- WHEN он добавляется
- THEN запись отклоняется
- AND значение не сохраняется и не логируется

#### Scenario: Секрет в старом факте
- GIVEN в файле уже есть факт со значением секрета
- WHEN владелец открывает `/memory` или историю
- THEN значение не показывается
- AND видно, что факт скрыт как содержащий секрет, без значения

### Requirement: Версия схемы проверяется
Хранилище ДОЛЖНО проверять поле версии: читать версию 2, переносить версию 1 и откладывать
файл незнакомой (более новой) версии в копию `memory.json.corrupt-<дата>`, не принимая его
за валидный.

#### Scenario: Файл версии 2
- GIVEN файл памяти содержит версию 2
- WHEN хранилище загружается
- THEN факты читаются в новой схеме
- AND файл не перезаписывается без изменений

#### Scenario: Файл будущей версии
- GIVEN файл содержит версию новее, чем понимает код
- WHEN хранилище загружается
- THEN файл откладывается в копию
- AND память стартует пустой, данные не подменяются молча

### Requirement: Миграция памяти
Хранилище ДОЛЖНО переносить память версии 1 в схему версии 2: до миграции создавать копию
`memory.json.v1.bak`, после миграции сразу записывать файл с `version: 2`, а при сбое записи
сохранять исходный файл и копию для повторной попытки. Старые факты ДОЛЖНЫ проходить скан
секретов: найденные не переносятся, в истории остаётся пометка без значения.

#### Scenario: Первый запуск после обновления
- GIVEN на диске память версии 1
- WHEN агент загружается
- THEN создана копия `memory.json.v1.bak`
- AND факты перенесены, файл сразу записан как версия 2
- AND факты с секретами не перенесены

#### Scenario: Сбой записи при миграции
- GIVEN миграция не смогла записать файл
- WHEN агент продолжает работу
- THEN исходный файл и `.v1.bak` на месте
- AND при следующем старте миграция повторяется

### Requirement: Откат памяти проверяется
Откат на предыдущую версию ДОЛЖЕН выполняться восстановлением `memory.json.v1.bak` до
запуска старого кода, потому что старый код версию не проверяет и перезаписывает файл как
версию 1.

#### Scenario: Откат релиза
- GIVEN память мигрирована на версию 2
- WHEN выполняется откат на предыдущий релиз
- THEN `.v1.bak` восстанавливается на место `memory.json`
- AND старый код видит прежние факты
