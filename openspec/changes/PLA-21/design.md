# Техническое решение

## Отмена проверки
`verify({..., signal})` проверяет `signal.aborted`:
- до начала и перед каждым портом;
- внутри портов `inspectDocument`, `inspectSpreadsheet`, `recalcSpreadsheet`,
  `renderDocument`, `runCodeChecks`, `askModel`.
Порты принимают `signal`, убивают дочерний процесс по abort и прерывают `fetch`
через `AbortSignal`. Если сигнал уже сработал, порт не вызывается вовсе.

Оркестратор после **каждой** стадии (execute, verify, repair, повторная verify) и перед
`classifyOutcome` проверяет `signal.aborted`; при отмене возвращает `cancelled` независимо
от статуса проверки. Поздний `unavailable` не превращается в `done`.

## Бюджет
- `createModelClient.askModel(prompt, { signal })` возвращает `{ text, usage }`;
  `verification.usage` прокидывается в результат проверки.
- Оркестратор учитывает `verification.usage` в бюджете.
- Перед проверкой передаётся остаток времени; `verify` запускается с производным
  сигналом (`AbortSignal.any([parent, timeout(remaining)])`), чтобы проверка не жила
  дольше остатка.
- После проверки: если бюджет исчерпан, итог не `done` — `partial` с причиной `budget`
  (или `failed`, если проверка провалена). Исправление при исчерпанном бюджете не
  начинается.
- Неизвестный расход по-прежнему явно помечается и блокирует бесплатные повторы.

## Быстрый ответ
`tryQuickAnswer` получает результат модели, но терминальный статус ставит не сам:
оркестратор получает исполнителя `quick` либо метод `finishQuick`, который проходит
те же стадии/бюджет/отмену. Быстрый путь больше не вызывает `journal.close(done)`
напрямую. Если быстрый слой отключён/не сработал, задача идёт в DSH как раньше.

## Завершение
`journal.close` и итоговый статус остаются в одном выходе оркестратора; адаптер входа
только доставляет и паркует вопрос/варианты. Очередь и восстановление остаются в
адаптере до этапа 2, но не меняют терминальный статус после отмены.

## Тесты
- `verify` с уже отменённым сигналом: ни один порт не вызван.
- Отмена во время `askModel`: fetch получает abort, статус `cancelled`.
- Отмена после первой проверки и после проверки исправления: `cancelled`.
- Бюджет: usage модели вычитается; исчерпанный бюджет после успешной проверки → не `done`.
- Быстрый ответ: проходит через оркестратор, получает `done` только его выходом.
