# Корректирующее изменение: отмена, бюджет и единый владелец цикла

Основание: проверка этапа 1 (PLA-19). PLA-20 не начинаем; его ветка `stage2-queue`
остаётся отдельно.

## Зачем
После установки этапа 1 остались четыре дефекта:

1. Отмена не останавливает проверку: `verify()` не принимает `signal`, поэтому модель,
   LibreOffice и тестовые процессы продолжают работу после отмены.
2. После повторной проверки исправленного результата сигнал не проверяется: при отмене
   оркестратор может вернуть `done`.
3. Бюджет неполный: клиент проверяющей модели теряет `usage`, остаток времени/токенов не
   ограничивает проверку, а исчерпание после успешной проверки не меняет итог.
4. Оркестратор владеет только циклом DSH → проверка → исправление; очередь,
   восстановление, ожидание ответа, завершение и быстрый ответ остаются в `AgentBot`.

## Что меняется
- Проверка получает сигнал и передаёт его во все порты: HTTP модели, LibreOffice,
  запуск проверок. Отмена прекращает работу до следующего внешнего вызова.
- Оркестратор проверяет сигнал после каждой стадии и перед финальным статусом; отмена
  всегда даёт `cancelled`, поздний результат проверки не меняет исход.
- Клиент модели возвращает `usage`; оркестратор учитывает его в бюджете, ограничивает
  проверку остатком времени и не выдаёт `done` при исчерпанном бюджете.
- Быстрый ответ идёт через оркестратор (отдельный исполнитель `quick`), а не ставит
  `done` самостоятельно. Завершение задачи — через общий выход оркестратора.

## Не входит
PLA-20 (SQLite-очередь), перенос очереди/восстановления в отдельный сервис, новые
агенты, GitHub-конвейер. Очередь и восстановление остаются адаптером входа, но не
владеют исполнением и терминальным статусом.

## Проверка
Регрессионные тесты: уже отменённый сигнал не вызывает модель/процессы; отмена после
первой проверки и после проверки исправления; budget exhausted при успешной проверке;
usage модели учитывается; быстрый ответ проходит через оркестратор. Полный прогон.
