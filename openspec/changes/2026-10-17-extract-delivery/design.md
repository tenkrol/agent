# Техническое решение

## Как устроено сейчас
`bot.mjs` → `reportResult`: собирает header по пяти условиям, обрезает ответ до
`maxAnswerChars`, добавляет диагностику stderr, подпись «N мин, шагов M, токенов X, ≈$Y»,
предупреждение о дорогой задаче (выше `taskTokenWarn`), в brief-режиме — заметки о вложениях
и пути на Диске; отдельно формирует строку статуса и шлёт сообщение.

## Предлагаемое решение
```
src/delivery/
  report.mjs  buildHeader, composeReportText, statusMarkdown
  index.mjs   публичный API домена
```
- `composeReportText` принимает готовые данные: `result`, `job`, лимиты, стиль отчёта,
  лимит длины ответа, хвост диагностики, пути архива, флаг подписи и числа подписи
  (минуты, шаги, токены, стоимость строкой). Домен не импортирует другие домены — только
  чистые правила текста.
- `statusMarkdown` — строка статуса: отмена/таймаут → header, иначе «✅ Задача N выполнена.».
- `bot.mjs` заменяет тело `reportResult` вызовом `composeReportText` и `statusMarkdown`.

## Влияние
- Правка одной функции в `bot.mjs`; тексты и условия сохранены дословно.
- Риск: расхождение в порядке частей — ловится тестами домена и существующими тестами бота.
- Откат: симлинк на предыдущий релиз.

## Альтернативы
- Вынести весь `reportResult` вместе с отправкой в отдельный класс — следующий шаг
  (`bot-link`/`core`), сейчас достаточно чистых правил текста.
- Оставить сборку в ядре и покрыть тестами — не решает задачу границ.
