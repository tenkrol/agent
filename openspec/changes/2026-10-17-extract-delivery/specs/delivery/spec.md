# Дельта для домена delivery

## ADDED Requirements

### Requirement: Как выглядит ответ — решает домен
Сборка текста ответа (заголовок, тело, диагностика, подпись, заметки) ДОЛЖНА происходить в
домене `delivery` из готовых данных. Ядро не склеивает текст ответа вручную.

#### Scenario: Обычная задача
- GIVEN задача завершилась успешно
- WHEN формируется ответ
- THEN домен собирает текст и подпись со стоимостью
- AND ядро передаёт только числа

### Requirement: Условия заголовка сохраняются
Заголовок ДОЛЖЕН различать отмену, превышение шагов, превышение бюджета, таймаут и код
ошибки ровно так же, как раньше.

#### Scenario: Лимит шагов
- GIVEN задача остановлена по лимиту шагов
- WHEN домен строит заголовок
- THEN в тексте есть причина и совет сузить задачу
- AND статус задачи не подменяется на «выполнена»

### Requirement: Длина ответа ограничена
Длинный ответ ДОЛЖЕН обрезаться до предела из настроек с пометкой об обрезке.

#### Scenario: Очень длинный ответ
- GIVEN ответ больше предела
- WHEN домен собирает текст
- THEN текст обрезан и помечен
- AND остальные части отчёта сохранены

### Requirement: Домен не зависит от других доменов
Сборка текста ДОЛЖНА использовать только переданные данные: числа, флаги и строку
стоимости. Импортов других доменов в `src/delivery/` быть не должно.

#### Scenario: Проверка границ
- GIVEN в домен добавляют импорт стоимости из `storage`
- WHEN запускается сторожевой тест
- THEN тест падает и указывает файл
