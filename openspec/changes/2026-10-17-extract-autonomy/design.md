# Техническое решение

## Как устроено сейчас
`observe.mjs` — сборка базовой линии, готовность, пороги, отчёт `/observe`. `alerts.mjs` —
триггеры, дедуп, тихие часы, сводка, классификация ошибок. `alerts-cli.mjs` — рантайм
таймера: читает наблюдения, оценивает триггеры, применяет дедуп/тишину/«стоп», шлёт через
`integrations/notify`, пишет аудит. Ядро импортирует `observe` и `alerts` для команд бота.

## Предлагаемое решение
```
src/autonomy/
  observe.mjs    метрики, базовая линия, готовность, черновик порогов
  alerts.mjs     триггеры, дедуп, тихие часы, сводка, классификация ошибок
  alerts-cli.mjs рантайм таймера
  index.mjs      публичный API домена
```
- Импорты внутри домена становятся `./observe.mjs`, внешние — `../config/index.mjs`,
  `../integrations/notify.mjs`.
- Юнит `agent-alerts.service` и установщик получают новый путь CLI
  (`/opt/agent/src/autonomy/alerts-cli.mjs`).
- Ядро (`bot.mjs`) продолжает импортировать наблюдателя для `/observe` и `/alerts` —
  это чтение, домен от этого не становится зависимым от ядра.

## Влияние
- Перенос трёх файлов, правка импортов в `bot.mjs`, двух тестах, юните и установщике.
- Риск: таймер не найдёт CLI — ловится проверкой `systemctl status agent-alerts` после
  деплоя; установщик подставляет путь через sed, поэтому правится в одном месте.
- Откат: симлинк на предыдущий релиз.

## Альтернативы
- Оставить автономию в корне — нарушает карту доменов и правило «ядро не тянет автономию».
- Вынести таймеры в отдельный процесс — избыточно: CLI уже отдельный и запускается systemd.
