# Техническое решение

## Как устроено сейчас
`tools/secrets.mjs` — один скрипт: читает `process.argv` и `SECRETS_PASSPHRASE`, тут же
шифрует/расшифровывает и печатает результат. Проверить крипто можно только запустив процесс
целиком; формат конверта описан в коде, но не проверяется отдельно.

## Предлагаемое решение
```
src/secrets/
  crypto.mjs  ключ из пароля (scrypt), seal/open, проверка конверта — чистые функции
  index.mjs   файлы: encryptFile/decryptFile/checkFile, SecretsError
  cli.mjs     разбор argv и SECRETS_PASSPHRASE, коды возврата
tools/secrets.mjs  обёртка: import '../src/secrets/cli.mjs'
tools/secrets.sh   обёртка с поиском node (пути обновлены под новый каталог)
```
- Конверт остаётся прежним: `{v:1, kdf:'scrypt', cipher:'aes-256-gcm', salt, iv, tag, data}`.
- Ошибки — `SecretsError` с кодом (2 — нет пароля/команды, 3 — не расшифровывается),
  ровно как раньше, чтобы скрипты деплоя не сломались.
- Значения в выводе не появляются: `check` печатает только имена переменных.

## Влияние
- Интерфейс обёрток не меняется: документация (`AGENTS.md`, `conventions.md`) остаётся верной.
- Риск: старый конверт не прочитается при ошибке в формате — ловится тестом с заранее
  зашифрованным образцом (фикстура создаётся в тесте тем же `seal`, плюс тест на неверный
  формат).
- Откат: предыдущий релиз через симлинк.

## Альтернативы
- Оставить скрипт и добавить только тесты на процесс — дешевле, но крипто остаётся
  непроверяемым по частям, а сторожевой тест не сможет отличить домен от скрипта.
- Вынести секреты в отдельный пакет — избыточно для одного процесса без зависимостей.
