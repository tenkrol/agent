# Контракт ассистент ↔ агент, версия 2 (черновик)

Статус: проект в изменении PLA-14. После архивации становится
`openspec/specs/bot-link/contract.md` и источником истины для обеих сторон.

Транспорт: HTTP по loopback через SSH-туннель; авторизация — `Authorization: Bearer <token>`.
Тела — JSON UTF-8, ответы — JSON. Входящий JSON — не больше 64 КиБ, текст задачи — не
больше `BRIDGE_MAX_TASK_CHARS`, файлы — не больше `FILES_MAX_BYTES`.

Версия 2 требует `requestId` во всех изменяющих запросах (`/v1/*`). Прежний `/bridge`
работает без него и остаётся совместимым входом.

## 1. Файлы
Файлы не передаются внутри JSON: они загружаются отдельно и упоминаются по `fileId`.

### Загрузка
`POST /v1/files` — `multipart/form-data`, поле `file`, токен обязателен.
Лимит размера — `FILES_MAX_BYTES` (по умолчанию 20 МиБ); больше — `413`.

Ответ `201`:
```json
{ "ok": true, "fileId": "f_7f3a1c", "name": "план.docx", "size": 12345, "mime": "application/vnd.openxmlformats-officedocument.wordprocessingml.document" }
```
`403` — загрузка не от настроенного ассистента; `400` — нет поля `file`.

### Получение
`GET /v1/files/:id` с тем же токеном — бинарное тело с `content-type` из метаданных.
Файлы результата доступны не меньше срока `OUTPUT_RETENTION_DAYS`; после истечения —
`410`, неизвестный `fileId` — `404`. Без токена файл не отдаётся.

Загруженные входные файлы и файлы результата хранятся раздельно; `fileId` непрозрачен и
не является путём. Произвольные пути и URL не принимаются.

## 2. Постановка задачи
`POST /v1/tasks`

```json
{
  "contract": 2,
  "requestId": "uuid или стабильный ключ запроса",
  "task": "полная формулировка поручения",
  "source": "assistant",
  "revisionOf": "необязательный id прошлой задачи",
  "route": {
    "platform": "telegram",
    "botId": "8414623999",
    "chatId": "433296567",
    "threadId": null,
    "messageId": 12345
  },
  "attachments": [
    { "kind": "document", "fileId": "f_7f3a1c", "name": "план.docx",
      "mime": "...", "size": 12345 }
  ],
  "context": {
    "facts": [
      { "text": "часовой пояс владельца — Europe/Moscow", "subject": "timezone",
        "validUntil": null }
    ]
  }
}
```

`requestId` ОБЯЗАТЕЛЕН и стабилен в пределах одного запроса: повтор после потери ответа
возвращает прежнюю задачу. `context.facts` — массив объектов `{ text, subject?, validUntil? }`
(согласовано с PLA-17); это факты ассистента для этой задачи, агент их не сохраняет.

Ответ `202`:
```json
{ "ok": true, "contract": 2, "taskId": "101034-1a", "state": "queued", "duplicate": false }
```

Ошибки: `400` (нет `requestId`/задачи, кривой JSON, неверный `fileId`), `401` (токен),
`409` (тот же `requestId` с другим телом), `413` (тело), `503` (не сохранено — задача не
принята).

`route` — куда возвращать вопрос и результат. Без `route` задача считается личной задачей
владельца в чате агента. `revisionOf` создаёт новую версию результата, сохраняя связь.

## 3. Состояние задачи
`GET /v1/tasks/:id`

```json
{
  "ok": true,
  "contract": 2,
  "task": {
    "id": "101034-1a",
    "execution": "running",
    "delivery": { "state": "pending", "target": "assistant", "attempts": 0 },
    "question": null,
    "result": null,
    "version": 1,
    "rootTaskId": "101034-1a",
    "revisionOf": null,
    "updatedAt": 1760000000000
  }
}
```

Когда задача ждёт ответа: `execution: "awaiting_owner"`, `question` содержит текст и
варианты. Когда результат готов: `result` содержит текст и файлы (`fileId`, `name`, `size`,
`mime`). `delivery` отражает только доставку и не подменяет состояние выполнения.
Состояние отмены (`execution: "cancelled"`) видно здесь же; отдельного события отмены нет.

## 4. Ответ на вопрос
`POST /v1/tasks/:id/reply`

```json
{ "contract": 2, "requestId": "reply-uuid", "text": "вариант 2", "variant": 2 }
```

`requestId` обязателен. Ответ `202`; задача продолжается с сохранённой сессией. Повтор с тем
же `requestId` возвращает прежний ответ и не запускает второй раз; тот же `requestId` с
другим телом — `409`.

## 5. Отмена
`POST /v1/tasks/:id/cancel` — `{ "contract": 2, "requestId": "cancel-uuid" }`.

`requestId` обязателен. Ответ `200`; задача в состоянии `cancelled`, выполнение
останавливается. Повтор с тем же `requestId` идемпотентен; для уже отменённой задачи ответ
успешный. Пользовательское событие отмены не отправляется: состояние доступно через
`GET /v1/tasks/:id`.

## 6. Ревизия результата
`POST /v1/tasks` с `revisionOf` и обязательным `requestId` — новая задача с `rootTaskId`
прежней, `version` на единицу больше. Агент использует прошлый результат и файлы как
входные материалы. Прежняя версия остаётся доступной (`GET /v1/tasks/:oldId`) и её файлы —
через `/v1/files/:id` согласно сроку хранения.

## 7. События доставки (агент → ассистент)
`POST <OUTBOX_URL>` — тот же адрес, что и раньше.

### Пользовательские события
Только `result` и `question`: они создают сообщение владельцу в исходном разговоре.

```json
{
  "contract": 2,
  "eventId": "101034-1a:result:1",
  "taskId": "101034-1a",
  "type": "result",
  "route": { "platform": "telegram", "botId": "...", "chatId": "...", "messageId": 12345 },
  "createdAt": 1760000000000,
  "attempt": 1,
  "text": "текст ответа (обрезан до DELIVERY_TEXT_CHARS)",
  "title": "Ответ агента",
  "files": [
    { "fileId": "f_9c21", "name": "отчёт.docx", "size": 2048, "mime": "...", "caption": "..." }
  ]
}
```

- `text` обрезается до `DELIVERY_TEXT_CHARS` (по умолчанию 3 500 символов) и отправляется с
  заголовком «Ответ агента» — прежнее поведение сохраняется.
- `question` содержит `text` (для совместимости) и `question: { text, variants: [{n, text}] }`.
- `eventId` — единый формат `<taskId>:<type>:<version>`, без sequence. Повтор всегда с тем же
  идентификатором; версия события равна версии результата задачи.

### Служебное событие `memory_proposal`
Служебные события не создают сообщение пользователю: решение принимает ассистент как
владелец личных фактов. В событии нет полей `text` и `title`, чтобы старый приёмник не
принял его за пользовательское сообщение.

```json
{
  "contract": 2,
  "eventId": "101034-1a:memory_proposal:1",
  "taskId": "101034-1a",
  "type": "memory_proposal",
  "createdAt": 1760000000000,
  "attempt": 1,
  "proposal": { "text": "отчёты делаю в формате X", "subject": "report-format",
                "kind": "preference", "scope": { "type": "global", "value": null } }
}
```

Отправляется только если ассистент объявил `capabilities.serviceEvents: true`. Иначе событие
не отправляется и не считается недоставленным.

### Подтверждение и повторы
Ответ ассистента `200`:
```json
{ "ok": true, "eventId": "<тот же>", "processed": true, "duplicate": false }
```
`processed: true` — подтверждение обработки (`ack`), после него агент событие больше не
отправляет. Если ассистент уже обработал `eventId`, он возвращает `processed: true` и
`duplicate: true`. Ошибка `5xx` или сеть — повтор с тем же `eventId` по расписанию
`DELIVERY_RETRY_MS`, не больше `DELIVERY_MAX_ATTEMPTS`. Ошибка `4xx` — терминальная.

Старый приёмник без `ack` получает `200` и не подтверждает обработку: агент фиксирует
`sent` и не считает доставку подтверждённой. Это осознанная деградация совместимости;
служебные события ему не отправляются.

## 8. Возможности и версия
`GET /v1/health` — `{ ok: true, service: "agent-bridge", contract: 2 }`.
`GET /v1/capabilities` — `{ contract: 2, tasks: true, files: true, reply: true, cancel: true,
revision: true, events: true, serviceEvents: true }`. Сторона, которая видит `contract: 2`,
пользуется новыми полями; иначе работает прежний `/bridge`.

## 9. Границы доверия и политика операций
- Контракт не расширяет права агента: подлинность запроса ассистента не разрешает
  произвольные действия. Операции задачи проверяются той же политикой, что и личные:
  рабочая папка и `cwd` — только разрешённые, сети/секретов/серверов нет.
- `requestId` обязателен для `/v1/tasks`, `/reply`, `/cancel`; без него — `400`.
- `route` принимается только для настроенного ассистента; чужие `chatId`/`botId`
  отклоняются.
- `attachments[].fileId` — только файлы, загруженные через `/v1/files` этим ассистентом;
  произвольные URL, пути и идентификаторы не принимаются.
- `GET /v1/files/:id` требует токен; файлы результата живут не меньше срока хранения.
- Секреты в поля контракта не попадают; значения не логируются.
