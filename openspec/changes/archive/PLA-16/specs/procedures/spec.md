# Дельта для домена procedures

## ADDED Requirements

### Requirement: Сохранение процедуры по явному запросу
Система ДОЛЖНА сохранять процедуру только по явному запросу владельца: назначение, входные
параметры, формат результата, критерии проверки и ограничения. Процедура не появляется
автоматически из повторяющегося запроса. Версия создаётся с обязательными полями
`purpose`, `taskTemplate`, `resultFormat`, `criteria`, `limits`: выведенные из задачи
заполняются сразу, невыведенные не придумываются.

#### Scenario: Сохранение из задачи
- GIVEN владелец выполнил задачу и просит сохранить её как процедуру
- WHEN из задачи выводятся все обязательные поля
- THEN создаётся версия 1 со статусом `active`
- AND процедура появляется в списке и доступна для `/procedure run`

#### Scenario: Не все поля выведены
- GIVEN из задачи нельзя вывести формат результата или критерии
- WHEN владелец просит сохранить процедуру
- THEN создаётся версия 1 со статусом `draft`
- AND процедура видна в списке, но запуск недоступен, пока поля не заполнены

#### Scenario: Без явного запроса
- GIVEN владелец повторяет похожие поручения
- WHEN он не просил сохранять процедуру
- THEN процедура не создаётся
- AND поведение задачи не меняется

### Requirement: Активация черновика
Версия в статусе `draft` НЕ ДОЛЖНА запускаться. Владелец ДОЛЖЕН заполнить недостающие
обязательные поля и явно активировать версию; только после активации `run` и расписание
становятся доступны. После активации версия неизменяема.

#### Scenario: Черновик не запускается
- GIVEN версия процедуры в статусе `draft`
- WHEN владелец пытается запустить процедуру
- THEN запуск отклоняется
- AND сообщение перечисляет недостающие поля

#### Scenario: Заполнение и активация
- GIVEN черновик без формата результата и критериев
- WHEN владелец заполняет их и активирует версию
- THEN версия становится `active`
- AND `run` использует её критерии

#### Scenario: Правка активной версии
- GIVEN у процедуры есть активная версия
- WHEN владелец меняет поле через `/procedure set`
- THEN создаётся новый черновик
- AND действующая версия не меняется до его активации

### Requirement: Версии процедуры неизменяемы
Активные и архивные версии НЕ ДОЛЖНЫ перезаписываться. Изменение процедуры создаёт новую
версию, а задача хранит использованную версию.

#### Scenario: Явная правка
- GIVEN процедура существует
- WHEN владелец явно меняет назначение или формат
- THEN создаётся новая версия
- AND прежняя версия остаётся доступной

#### Scenario: Разовая корректировка
- GIVEN владелец просит сократить текущий отчёт
- WHEN агент выполняет просьбу
- THEN изменение относится к текущему результату
- AND процедура не меняется

### Requirement: Запуск создаёт отдельную задачу с версией
Ручной запуск и запуск по расписанию ДОЛЖНЫ создавать отдельную задачу, фиксировать версию
процедуры и использовать её критерии результата. Запуск возможен только для активной версии
с заполненными обязательными полями.

#### Scenario: Еженедельный обзор
- GIVEN сохранена и активирована процедура подготовки обзора
- WHEN владелец запускает её вручную или по расписанию
- THEN создаётся отдельная задача
- AND фиксируется версия процедуры
- AND используются её критерии результата

#### Scenario: Правка между запусками
- GIVEN процедура изменена между двумя запусками
- WHEN наступает следующий запуск
- THEN новая задача использует активную версию
- AND уже созданные задачи сохраняют прежнюю версию

### Requirement: Ограничения процедуры не выше глобальных
Процедура НЕ ДОЛЖНА превышать глобальные лимиты задачи и не даёт новых прав, команд или
доступа.

#### Scenario: Слишком большой бюджет
- GIVEN процедура просит бюджет больше глобального
- WHEN процедура сохраняется или запускается
- THEN система отклоняет превышение
- AND объясняет допустимый предел

### Requirement: Процедура описывает формат и проверку
Процедура ДОЛЖНА содержать формат результата и критерии проверки в формате PLA-15
(`id`, `text`, `kind`, `required`, `source`); при запуске они попадают в задачу и в
проверку результата.

#### Scenario: Проверка по критериям процедуры
- GIVEN процедура требует разделы отчёта
- WHEN результат проверяется
- THEN критерии процедуры обязательны
- AND отчёт показывает, какие из них пройдены

#### Scenario: Источник критерия
- GIVEN критерий процедуры выведен из просьбы владельца
- WHEN он сохраняется в версии
- THEN у него есть `source` — фраза владельца или «минимальная проверка типа»
- AND при проверке видно, откуда критерий взялся
