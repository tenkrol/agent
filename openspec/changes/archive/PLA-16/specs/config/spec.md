# Дельта для домена config

## ADDED Requirements

### Requirement: Настройки процедур
Домен `config` ДОЛЖЕН читать, валидировать и отдавать домену `procedures` настройки
хранения версий, с значениями по умолчанию и понятной ошибкой при старте:

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `PROCEDURES_MAX_VERSIONS` | `20` | сколько версий одной процедуры хранится |
| `PROCEDURES_RETENTION_DAYS` | `365` | сколько дней хранятся удалённые процедуры и архивные версии |

Требования к значениям:
- `PROCEDURES_MAX_VERSIONS` — целое от 1 до 200; предел применяется только к архивным
  версиям и не удаляет версии, на которые ссылаются задачи;
- `PROCEDURES_RETENTION_DAYS` — целое от 1 до 3650; значение меньше `OUTPUT_RETENTION_DAYS`
  (срок хранения результатов) НЕ ДОПУСКАЕТСЯ, иначе версия, на которую ссылается задача,
  может исчезнуть раньше результата;
- неверное значение ДОЛЖНО давать `ConfigError` при старте с именем переменной и границами,
  не раскрывая секретов.

#### Scenario: Значения по умолчанию
- GIVEN переменные процедур не заданы
- WHEN сервис запускается
- THEN включаются значения по умолчанию из таблицы
- AND процедуры хранят не больше 20 версий и 365 дней архивных записей

#### Scenario: Неверный предел
- GIVEN `PROCEDURES_MAX_VERSIONS=0`
- WHEN сервис запускается
- THEN старт прерывается ошибкой `PROCEDURES_MAX_VERSIONS: …`
- AND сообщение не содержит значений секретов

#### Scenario: Срок меньше хранения результатов
- GIVEN `PROCEDURES_RETENTION_DAYS` меньше `OUTPUT_RETENTION_DAYS`
- WHEN конфиг собирается
- THEN старт прерывается ошибкой `PROCEDURES_RETENTION_DAYS: …` с объяснением минимума
- AND версии, на которые ссылаются задачи, не могут быть удалены раньше результата

#### Scenario: Предел числа версий и ссылки задач
- GIVEN у процедуры больше архивных версий, чем `PROCEDURES_MAX_VERSIONS`
- WHEN выполняется уборка
- THEN удаляются самые старые архивные версии
- AND версии, на которые ссылаются задачи, сохраняются

### Requirement: Настройки процедур не дублируются
Ключи процедур ДОЛЖНЫ читаться только в `config`; домен `procedures` и `storage` получают
готовые значения и НЕ ДОЛЖНЫ читать `process.env` или собственные переменные окружения для
этих настроек.

#### Scenario: Чтение в обход
- GIVEN в `src/procedures/` появляется чтение `process.env.PROCEDURES_MAX_VERSIONS`
- WHEN запускается сторожевой тест
- THEN тест падает и указывает файл
- AND значение переносится в `config`
