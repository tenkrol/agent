# Техническое решение

## Как устроено сейчас
`bridge-http.mjs` принимает `POST /bridge` с bearer-токеном, проверяет длину задачи и
отдаёт ответ боту. `notify.mjs` шлёт текст в Telegram напрямую (для алертов, чтобы не
зависеть от процесса бота). `mirrorToAssistant` в `bot.mjs` делает `fetch` на точку приёма
чат-бота с `OUTBOX_TOKEN`, молча проглатывая ошибки.

## Предлагаемое решение
```
src/bot-link/
  bridge-http.mjs  входящий приём задач (протокол, авторизация)
  mirror.mjs       правила зеркалирования ответа
  index.mjs        публичный API домена
src/integrations/
  notify.mjs       отправка в Telegram для алертов (внешний клиент)
  outbox.mjs       postOutbox: HTTP-вызов точки приёма чат-бота
```
- `mirror.mjs` решает, что зеркалировать (обрезка 3 500 символов, заголовок «Ответ агента»,
  молчание при ошибке), а `postOutbox` — единственное место с `fetch`.
- `bot.mjs` больше не содержит сетевого кода: импортирует `mirrorToAssistant` из домена.
- `notify.mjs` переезжает в `integrations`, потому что это клиент Telegram, а не правило
  связи; `autonomy` продолжает получать его как порт.

## Влияние
- Механический перенос двух файлов, один новый integration-клиент, одна новая функция
  зеркалирования; импорты в `index.mjs`, `alerts-cli.mjs`, `bot.mjs`, тестах.
- Риск: забытый импорт — ловится прогоном 319 тестов.
- Откат: симлинк на предыдущий релиз.

## Альтернативы
- Оставить `mirrorToAssistant` в `bot.mjs` — ядро продолжит ходить в сеть.
- Всю связь отдать в `integrations` — смешает протокол («что такое задача от бота») с
  транспортом.
