# Дельта для домена architecture

## ADDED Requirements

### Requirement: Новый домен verification
Контроль результата ДОЛЖЕН жить в отдельном домене `src/verification/`: вывод критериев,
проверки по типам результата и итоговый статус. Домен НЕ ДОЛЖЕН запускать процессы, ходить
в сеть и импортировать другие домены — он получает порты от ядра.

#### Scenario: Проверка документа
- GIVEN результат — документ
- WHEN ядро вызывает проверку
- THEN домен использует переданный порт инспекции документа
- AND сам не запускает LibreOffice и не знает его пути

#### Scenario: Нарушение границы
- GIVEN в `src/verification/` появляется вызов процесса или сети
- WHEN запускается сторожевой тест
- THEN тест падает и указывает файл

### Requirement: Домены-исполнители поставляют порты
Проверки, требующие процессов или сети, ДОЛЖНЫ быть реализованы в своих доменах и переданы
в `verification` как порты: инспекция документов и таблиц — `tools`, прогон проверок кода —
`execution`, модельные проверки — `integrations`.

#### Scenario: Недоступный порт
- GIVEN порт проверки не подключён
- WHEN проверка требуется
- THEN домен возвращает статус «недоступно»
- AND не выдаёт результат за проверенный

### Requirement: Зависимости домена verification
`core` МОЖЕТ вызывать `verification`; `verification` зависит только от `config` и типов,
которые передаёт ядро. Обратные и циклические зависимости запрещены.

#### Scenario: Импорт домена
- GIVEN проверке нужен разбор DOCX
- WHEN выбирается место кода
- THEN разбор живёт в `tools`, а проверка получает результат через порт

## MODIFIED Requirements

### Requirement: Таблица доменов и направления зависимостей
Таблица доменов в этой спеке ДОЛЖНА включать `verification` — «контроль результата:
критерии, проверки по типам, итоговый статус»; направления зависимостей ДОЛЖНЫ разрешать
`core → verification`. `verification` не импортирует другие домены: проверки, требующие
процессов или сети, приходят портами от `tools`, `execution`, `integrations`; обратные и
циклические зависимости запрещены.

#### Scenario: Новая строка таблицы
- GIVEN изменение PLA-15 архивируется
- WHEN дельта вливается в спеку architecture
- THEN в таблице доменов появляется `verification`
- AND в правилах зависимостей разрешено `core → verification`

#### Scenario: Проверка границы
- GIVEN `verification` импортирует `execution` напрямую
- WHEN сторожевой тест проверяет зависимости
- THEN тест падает
- AND связь идёт через порт
