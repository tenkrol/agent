# Дельта для домена core

## ADDED Requirements

### Requirement: Управление памятью командами
Ядро ДОЛЖНО позволять владельцу просматривать действующую память, её историю, явно
исправлять устаревший факт, задавать срок актуальности и забывать факт.

#### Scenario: Просмотр
- GIVEN в памяти есть действующие и заменённые факты
- WHEN владелец вызывает `/memory`
- THEN видны действующие факты по видам и областям с датами и источником
- AND история доступна отдельной командой

#### Scenario: Явное исправление
- GIVEN сохранён устаревший факт
- WHEN владелец явно сообщает новый с тем же предметом
- THEN новый становится действующим
- AND прежний не используется и виден в истории

### Requirement: Показ памяти не раскрывает секреты
Команды `/memory` и `/memory history` НЕ ДОЛЖНЫ показывать значения секретов: такие
фрагменты вырезаются или факт скрывается с пометкой без значения, включая факты, попавшие
в файл до обновления.

#### Scenario: Секрет в истории
- GIVEN в истории памяти есть факт со значением секрета
- WHEN владелец открывает `/memory history`
- THEN значение не показывается
- AND видно, что факт скрыт как содержащий секрет, без значения
- AND в лог попадает только имя ключа

### Requirement: Проверка отчёта на секреты
Перед отправкой отчёта ядро ДОЛЖНО проверить текст на значения известных секретов и
вырезать их, сообщив владельцу, что фрагмент был вырезан.

#### Scenario: Секрет в результате
- GIVEN собранный отчёт содержит значение секрета
- WHEN отчёт готов к отправке
- THEN значение вырезается
- AND владелец получает предупреждение без значения
- AND секрет не попадает в лог

### Requirement: Разделение владельцев памяти
Агент ДОЛЖЕН сам хранить (а) рабочий контекст задач и (б) предпочтения, которые владелец
явно сообщил агенту для его работы. Личные факты, переданные ассистентом, ДОЛЖНЫ
использоваться только в текущей задаче и НЕ ДОЛЖНЫ сохраняться агентом. Долговременное
хранение личных фактов — решение ассистента.

#### Scenario: Личный факт в задаче
- GIVEN ассистент передал личные факты для задачи
- WHEN задача завершена
- THEN факты не остались в памяти агента
- AND другие задачи их не видят

#### Scenario: Рабочий факт
- GIVEN агент вывел устойчивый рабочий факт
- WHEN он хочет сохранить его навсегда
- THEN уходит предложение `memory_proposal` ассистенту
- AND молчаливая запись личного факта не выполняется

#### Scenario: Предпочтение для работы агента
- GIVEN владелец явно сказал агенту, что отчёты нужны в формате DOCX
- WHEN агент сохраняет это предпочтение
- THEN запись остаётся в памяти агента как его рабочая настройка
- AND она не считается личным фактом ассистента

### Requirement: Предложение памяти не применяется молча
Предложение `memory_proposal` ДОЛЖНО доставляться ассистенту как service-событие, только
если ассистент объявил `capabilities.serviceEvents: true`. Если поддержка объявлена, но
ассистент недоступен, предложение остаётся в очереди доставки и повторяется; если поддержки
нет — событие не отправляется и не считается ошибкой доставки. До подтверждения ассистента
(или без поддержки service-событий) факт НЕ ДОЛЖЕН сохраняться в долговременной памяти
агента.

#### Scenario: Ассистент недоступен
- GIVEN агент сформировал предложение памяти
- WHEN доставка ассистенту не удалась
- THEN предложение ждёт в очереди доставки
- AND факт не записан в `memory.json`
- AND факт живёт только в текущей задаче

#### Scenario: Ассистент без поддержки
- GIVEN ассистент не объявил `capabilities.serviceEvents`
- WHEN у агента появляется предложение памяти
- THEN событие не отправляется
- AND это не считается ошибкой доставки
- AND факт не записан в `memory.json`

#### Scenario: Ассистент принял решение
- GIVEN ассистент подтвердил обработку предложения
- WHEN решение о записи принято на стороне ассистента
- THEN агент не дублирует запись у себя
- AND событие больше не повторяется
