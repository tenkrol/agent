# Дельта для домена architecture

## MODIFIED Requirements

### Requirement: Направление зависимостей
Разрешено: `core → execution → tools → integrations`, `delivery → integrations`,
`autonomy → storage`, `bot-link → integrations`, все домены → `config`. Дополнительно
`storage`, `execution` и `core` МОГУТ использовать связанный read-only guard-порт домена
`secrets` (`contains`, `redact`) для проверки текста на значения секретов; это единственное
разрешённое направление в `secrets` помимо `ops` и `config`. Guard-порт создаётся в точке
сборки из значений `config`; домены получают уже связанный порт и НЕ получают доступа к
значениям секретов, шифртексту, файлам секретов и `process.env`. Guard сам окружение не
читает. Обратные зависимости (например, `integrations → core`) запрещены; циклические —
запрещены.

#### Scenario: Импорт «назад»
- GIVEN агент хочет из `integrations` импортировать функцию из `core`
- WHEN это происходит
- THEN правило нарушено: нужная функция переносится в общий домен (`tools`, `storage`)
  или в порт

#### Scenario: Guard секретов
- GIVEN `storage`, `execution` или `core` проверяет текст на секреты
- WHEN используется guard-порт из `secrets`
- THEN значения приходят из `config` аргументами
- AND домен не читает шифртекст, файлы секретов и `process.env`

### Requirement: Секреты — отдельный домен
Значения ключей ДОЛЖНЫ храниться только в шифртексте `secrets/agent.env.enc`; в репозитории
допустим только реестр имён `secrets/keys.md` без значений и инструменты расшифровки.
Домены НЕ ДОЛЖНЫ читать файлы секретов напрямую: значения приходят из окружения процесса,
а `config` отдаёт только нужные домену поля. Домен `secrets` ДОЛЖЕН предоставлять чистый
guard-порт (`src/secrets/guard.mjs`) для проверки и вырезания значений; guard не зависит от
других доменов и не читает окружение сам. Использовать guard-порт МОГУТ `storage`,
`execution` и `core` — только для проверки/вырезания, без получения значений секретов.

#### Scenario: Новая машина
- GIVEN репозиторий склонирован на новую машину
- WHEN выполняется `bash tools/secrets.sh decrypt`
- THEN появляется окружение с правами 600
- AND без пароля (он вне репозитория) расшифровка невозможна

#### Scenario: Задача просит ключ
- GIVEN задаче нужен доступ к внешнему API
- WHEN собирается промпт и окружение задачи
- THEN значения секретов в промпт не попадают
- AND ключ остаётся в окружении сервиса, а в логи попадает только имя ключа

#### Scenario: Ротация
- GIVEN ключ нужно заменить
- WHEN выполняется ротация
- THEN новое значение попадает в шифртекст и на сервер
- AND старое значение не остаётся ни в репозитории, ни в истории переписки

#### Scenario: Guard не раскрывает значения
- GIVEN домен вызывает guard-порт
- WHEN проверяется текст
- THEN возвращается только признак или очищенный текст
- AND домен не получает значений секретов; имя ключа может вернуться только для журнала
