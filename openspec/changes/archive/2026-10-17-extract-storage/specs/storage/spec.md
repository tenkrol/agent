# Дельта для домена storage

## ADDED Requirements

### Requirement: Состояние пишет только домен storage
Запись файлов состояния ДОЛЖНА происходить внутри `src/storage/`. Остальные домены
получают готовые хранилища через публичный API домена.

#### Scenario: Запись в обход домена
- GIVEN в `src/` вне `src/storage/` появляется запись файла состояния
- WHEN запускается сторожевой тест
- THEN тест падает и указывает файл

### Requirement: Запись атомарна
Запись ДОЛЖНА идти через временный файл и переименование, чтобы сбой посреди записи не
оставлял пустой или частичный файл состояния; временные файлы не остаются после успеха.

#### Scenario: Успешная запись
- GIVEN хранилище сохраняет состояние
- WHEN запись завершена
- THEN файл читается как валидный JSON
- AND рядом не осталось временных файлов

### Requirement: Битый файл откладывается, а не теряется
Если файл не читается как JSON или имеет незнакомую версию, ДОЛЖНА оставаться его копия
`<файл>.corrupt-<дата>`, и только после этого работа продолжается с пустым состоянием.

#### Scenario: Повреждённый JSON
- GIVEN файл состояния повреждён
- WHEN хранилище загружается
- THEN копия повреждённого файла сохранена рядом
- AND агент стартует с пустым состоянием и пишет об этом в журнал

### Requirement: Версия схемы проверяется
Хранилище ДОЛЖНО проверять поле версии и не принимать файл незнакомой версии как валидный.

#### Scenario: Файл будущей версии
- GIVEN файл содержит версию схемы новее, чем понимает код
- WHEN хранилище загружается
- THEN файл откладывается в копию, данные не подменяются
