# Изменение: вынести состояние и учёт в домен storage

## Зачем
Состояние агента (курсор, сессии, память, журнал задач, расход) раскидано по пяти
модулям в `src/`, и каждый сам решает, как писать файл. Атомарная запись с версией схемы
есть только в `state.mjs`; остальные пишут «как получится», а битый файл просто
игнорируется — то есть теряется без следа.

## Что меняется
Появляется домен `src/storage/`: все пять модулей переезжают туда, общая запись выносится
в `atomic.mjs`, битый файл при чтении откладывается в копию `<файл>.corrupt-<дата>`, а не
молча затирается. Публичный API домена — `src/storage/index.mjs`.

## Чего не делаем
- Не меняем формат файлов и ключи состояния — данные, записанные прошлой версией, читаются.
- Не добавляем миграции схем: версия уже есть в `state.mjs`, остальные получат её отдельным
  изменением, если понадобится.
- Не меняем команды и отчёты: поведение агента то же.

## Как проверяем
- Все существующие тесты зелёные; новые тесты: атомарная запись, копия битого файла,
  версия схемы, отсутствие временных файлов после записи.
- Сторожевой тест: файлы состояния пишет только домен `src/storage/`.
- Живой прогон: деплой, сервис active, задача через мост.
