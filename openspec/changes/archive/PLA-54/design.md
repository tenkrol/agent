# Техническое решение

`parseTaskRequest` нормализует `principal.userId/scopeId` с ограничением длины.
`submitV2Task` использует его для `job.userId` и `job.scopeId`; при отсутствии
владелец безопасно выводится из уже проверенного delivery route, затем из
`alertChatId` для запроса без маршрута.

`taskState` публикует только идентификаторы principal, уже сохранённые в журнале.
Это позволяет доверенному backend бота проверить ownership до выдачи деталей или
отмены. Маршрут результата остаётся независимым и не меняется.

Риск совместимости закрывается тестом старого запроса без principal и новым
двухпользовательским тестом маршрута, activity и usage.
