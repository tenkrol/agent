# PLA-54: правильный principal задач из моста

## Зачем

Контракт v2 сохраняет маршрут исходного чата, но владельцем, областью, расходом и
лимитами любой задачи назначает системный `alertChatId`. В двухпользовательском
боте это смешивает учёт и делает корректную ACL-фильтрацию невозможной.

Владелец после отчёта явно поручил исправить найденные ошибки.

## Что меняется

- контракт v2 валидирует необязательный `principal`;
- новые клиенты задают владельца и область отдельно от delivery route;
- задача, activity, usage и персональный лимит используют этот principal;
- GET задачи возвращает principal для проверки доступа вызывающей стороной.

## Чего не делаем

- не принимаем principal из текста задачи;
- не меняем bearer-аутентификацию моста;
- старые клиенты без principal не ломаем.
