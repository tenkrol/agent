# Архив изменений

Папки названы по маске `PLA-<номер по порядку>`. Номер — сквозной для проекта, без дат:
дата закрытия видна в `HANDOFF.md`, содержание — в описании ниже и в `proposal.md`.

| Папка | Что это |
|---|---|
| `PLA-1` | Карта архитектуры: 11 доменов, правила зависимостей, очередь работ (по решению владельца добавлен домен `secrets`) |
| `PLA-2` | `extract-config` — настройки агента (`src/config/`), `process.env` только там |
| `PLA-3` | `extract-secrets` — секреты (`src/secrets/`), шифртекст трогает только домен |
| `PLA-4` | `extract-storage` — состояние и учёт (`src/storage/`), атомарная запись и копия битого файла |
| `PLA-5` | `extract-integrations` — внешний мир (`src/integrations/`), сеть только там |
| `PLA-6` | `extract-execution` — исполнение задач (`src/execution/`): DSH, cgroup, промпт, разбор ответа |
| `PLA-7` | `extract-tools` — инструменты (`src/tools/`): вложения, OCR, vision, голос |
| `PLA-8` | `extract-delivery` — как выглядит ответ (`src/delivery/`) |
| `PLA-9` | `extract-bot-link` — связь с чат-ботом (`src/bot-link/`), ядро без сети |
| `PLA-10` | `extract-autonomy` — наблюдатель и алерты (`src/autonomy/`) |
| `PLA-11` | `slim-core` — ядро только оркестрирует (`src/core/`), журналирование в `src/ops/` |
| `PLA-12` | Исправление: в чат-бота уходит только результат и запрос информации |
| `PLA-13` | Надёжность: долговечная очередь, состояния и переходы, восстановление после сбоя, `/continue`, защита от повторной постановки |
| `PLA-15` | Проверка результата: домен `verification`, критерии, документы/таблицы/код/исследование, `VERIFY=false`, повторное исправление |
| `PLA-14` | Контракт v2 с ассистентом: `/v1/tasks`, состояние/ответ/отмена, файлы, события с `eventId` и `ack`, маршрут, ревизии; старый `/bridge` совместим |
| `PLA-16` | Личные процедуры: назначение, параметры, формат, критерии, неизменяемые версии, запуск и расписания, лимиты |
| `PLA-17` | Управляемая память: виды/происхождение/область/срок/история, замена факта, отбор в задачу, защита от секретов |
| `PLA-18` | Проверка таблиц и исследований: пересчёт каждого файла с `unavailable` при сбое, сохранение ошибок формул, JSON-вердикт исследования по критериям, границы фактчекинга |
| `PLA-19` | Этап 1 агентной системы: оркестратор и адаптер DSH, единая отмена, общий остаток бюджета, стадии и восстановление без смены контракта |
| `PLA-21` | Корректирующее: отмена проверки до модели/LibreOffice/процессов, бюджет проверки, быстрый путь через оркестратор |
| `PLA-22` | Этап 1 завершён: lifecycle владеет очередью, восстановлением, awaiting и терминальными переходами; планирование в общем контексте |
| `PLA-23` | SQLite fencing: requeue с payload/generation, cancelAll, owner/lease/status в complete, восстановление до TTL, программный запрет workers>1 |
| `PLA-20` | Этап 2: SQLite-очередь с арендами/поколениями, fencing, восстановление до TTL и после краха, изоляция workspace на задачу, workers=2 |
| `PLA-24` | E0: остановка по потере аренды, атомарное принятие результата/outbox, stale-защита, сверка и восстановление SQLite↔JSONL |
| `PLA-25` | E1: реестр агентов с метаданными, fresh session на per-task запуск, retention tasks, лимит задач пользователя |
| `PLA-26` | E2: журнал активности, `/v1/agents`, `/v1/activity`, `/v1/usage`, профили моделей и учёт кеша без двойного суммирования |
| `PLA-29` | E4: заявка из сообщения, анализ компонентов, публикация компонентных OpenSpec-черновиков и manifest с changeId/SHA |
| `PLA-31` | E5: реализация заявки агентом-разработчиком в изолированном checkout, ветка `impl/<REQ>-<changeId>`, POST /v1/implement |
| `PLA-33` | E6: проверки после DSH, repair-цикл и запрет публикации красной ветки impl |
| `PLA-34` | E7: подтверждение, повторные проверки, merge в main и установка проверенной реализации (install — владельцем/root) |
| `PLA-35` | E8: файловый исполнитель `files`, профиль модели и выбор исполнителя по задаче |
| `PLA-36` | E9: агент-наблюдатель `monitor`, маршрутизация host-задач |
