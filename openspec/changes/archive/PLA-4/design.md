# Техническое решение

## Как устроено сейчас
`src/state.mjs` — JSON-хранилище с версией 1, атомарной записью (временный файл + rename),
сериализацией писателей и дебаунсом. `src/memory.mjs`, `src/tasks.mjs`, `src/usage.mjs`,
`src/pricing.mjs` лежат рядом с ядром; `pricing` — чистые расчёты, остальные пишут файлы.

## Предлагаемое решение
```
src/storage/
  state.mjs    курсор и сессии (перенос без изменений + общая атомарная запись)
  memory.mjs   факты о владельце
  tasks.mjs    журнал задач
  usage.mjs    расход токенов
  pricing.mjs  расчёты стоимости (чистые функции)
  atomic.mjs   writeAtomic + quarantineCorrupt
  index.mjs    публичный API домена
```
- `writeAtomic(file, text)` пишет во временный файл рядом и делает rename — как сейчас,
  но в одном месте и для всех.
- `quarantineCorrupt(file)` при ошибке чтения копирует файл в `<файл>.corrupt-<ISO дата>`
  и возвращает путь; `StateStore` вызывает его до замены состояния.
- Импорты в `src/` и `test/` переключаются на `./storage/<модуль>.mjs` механически.

## Влияние
- Дифф механический: перенос пяти файлов и строки импортов; поведение не меняется.
- Риск: забытый импорт — ловится полным прогоном и стартом сервиса.
- Откат: переключение симлинка на предыдущий релиз.

## Альтернативы
- Оставить модули на месте и добавить только копию битого файла — дешевле, но домен
  останется размазанным по `src/`, а общая запись так и будет дублироваться.
- Ввести журнал с миграциями схем — избыточно: версия уже есть, миграций пока нет.
