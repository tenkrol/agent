# Техническое решение

## Как устроено сейчас
`src/verification/index.mjs`, ветка `spreadsheet`:
- `inspectSpreadsheet` вызывается для всех файлов, но `opens`/`text` только накапливаются;
- `recalcSpreadsheet` вызывается только для `sheets[0]`, его `ok` игнорируется;
- `errors` берутся из пересчёта; при исключении/недоступности массив остаётся пустым, и
  критерий `computation` получает `passed` («ошибки формул не найдены»);
- имя файла в свидетельстве не фигурирует.

`src/verification/index.mjs`, ветка `research`:
- промпт просит строку «ИСТОЧНИКИ: да|нет…», ответ разбирается регулярками;
- `hasSources`/`hasAssumptions` ищут слова в самом ответе и могут дать `passed` без вердикта;
- схемы ответа нет, неразобранный вердикт не ведёт к `unavailable`.

## Предлагаемое решение

### Таблицы
Для каждого табличного файла собирается свидетельство:
```js
{
  file: 'outbox/смета.xlsx',
  opens, inspectError,
  initialErrors,        // ошибки формул, видимые при чтении
  recalc: { ok, errors, text, error } | undefined
}
```
Критерии:
- `opens`: `passed`, только если все файлы открылись; иначе `failed` с именами;
- `data`: `passed`, только если во всех файлах есть текст; иначе `failed` с именами;
- `computation`:
  - нет порта пересчёта → `unavailable`;
  - для любого файла пересчёт бросил исключение/вернул `ok:false`/не вернул результат →
    `unavailable` с причиной и именем файла;
  - в пересчёте есть ошибки формул → `failed` (ошибки в свидетельстве);
  - пересчёт `ok:true`, ошибок нет, но при чтении были ошибки → `failed`:
    исходный файл содержит ошибку, а проверенная версия не сохранена и не выдана;
  - `passed` — только когда все файлы открылись, пересчитаны с `ok:true` и в них не было
    ошибок ни до, ни после.
Обнаруженные ошибки никогда не заменяются фразой «ошибок нет»; причина недоступности
всегда попадает в `limitations` и в свидетельство.

### Исследования
Промпт проверяющей модели требует строгий JSON без пояснений:
```json
{
  "sources":     { "status": "passed|failed|unavailable", "reason": "…" },
  "linkage":     { "status": "passed|failed|unavailable", "reason": "…" },
  "assumptions": { "status": "passed|failed|unavailable", "reason": "…" }
}
```
- ответ очищается от code fence, извлекается первый JSON-объект;
- проверяется схема: все три ключа, статус из набора, непустая причина; иначе критерий
  получает `unavailable` с причиной «вердикт не разобран»;
- ключевые слова в тексте ответа НЕ используются как доказательство;
- в `limitations` всегда добавляется «фактическая проверка содержимого источников не
  выполнялась: проверялся только ответ»;
- исключение/таймаут модели → все критерии `unavailable`, итог не `passed`.

### Критерии
`deriveCriteria` для `research` добавляет три обязательных критерия: `sources`,
`linkage`, `assumptions` (с `source: «минимальная проверка типа»`). Старые сохранённые
задачи без `linkage` проверяются по имеющимся критериям; схема задачи не мигрируется.

### Влияние
Меняется только `src/verification/index.mjs` и `src/verification/criteria.mjs`; отчёт
`delivery` уже показывает `unavailable` и `limitations`. Порты не меняются. Откат —
симлинк на предыдущий релиз.

### Альтернативы
- Считать `ok:false` успехом при пустых ошибках — это и есть текущий дефект; отвергнуто.
- Проверять исследование регулярками — не даёт доказательства; отвергнуто.
- Сохранять пересчитанный файл и выдавать его — меняет поведение доставки и требует
  отдельного решения; в этом изменении не делаем.
