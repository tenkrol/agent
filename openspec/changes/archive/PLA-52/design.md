# Техническое решение

## Ограниченный пул очереди

`AgentBot` хранит множество активных drain-циклов. Планировщик создаёт циклы только
пока есть ожидающие задачи и свободные слоты, максимум `QUEUE_WORKERS`. Общий promise
ожидает также циклы, запущенные при освобождении слота.

## Отмена и восстановление

Lifecycle предоставляет поиск активного запуска по id. Отмена контракта обращается к
нему, а остановка сервиса отменяет все активные контроллеры. Поля `kind`, `requestId`,
`revision` и `retry` входят в долговечную запись задания и восстанавливаются из неё.
До очистки task-workspace journal загружается; защищаются только нетерминальные записи.

## Доставка и проверки

Личный ответ записывается в `DeliveryStore` с постоянным eventId до снятия SQLite
outbox. Ошибка Telegram оставляет запись pending для ограниченного повтора. Быстрый и
обычный пути используют один механизм.

`runCodeChecks` превращает отменённый signal в `AbortError`. Workflow реализации
проверяет signal на границах DSH, checks, repair и push; отмена записывает состояние
cancelled и не публикует ветку.

## Изоляция repair

Оркестратор передаёт `workspaceDir` повторному executor-вызову. Поэтому DSH выбирает
тот же cwd и корень песочницы, что в первоначальной попытке.
