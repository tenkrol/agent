# PLA-52: исправление ошибок надёжности очереди и выполнения

## Зачем

Аудит commit `6157f92` воспроизвёл семь ошибок на границах очереди, исполнения,
проверки и доставки: число параллельных запусков превышает `QUEUE_WORKERS`, отмена
второй активной задачи не останавливает её, ошибка Telegram считается успешной
доставкой, JSONL-восстановление теряет тип implement-задачи, отмена позволяет
пропустить проверки перед публикацией, очистка удаляет workspace незавершённой задачи,
а repair запускается вне изолированного workspace.

## Что меняется

- очередь запускает не больше настроенного числа обработчиков;
- активная задача отменяется по id, включая параллельные задачи;
- личный текстовый ответ проходит через долговечную очередь доставки и повторяется;
- журнал сохраняет поля типизированной implement-задачи;
- отменённые проверки не считаются зелёными и не допускают публикацию;
- journal загружается до очистки workspace, незавершённые задачи защищены;
- repair получает тот же `workspaceDir`, что основной запуск.

## Чего не делаем

- не меняем внешние HTTP-контракты и форматы команд Telegram;
- не меняем схему SQLite;
- не выполняем deploy и не обращаемся к боевым сервисам в рамках локальной проверки.
