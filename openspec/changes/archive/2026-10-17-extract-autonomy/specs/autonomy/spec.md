# Дельта для домена autonomy

## ADDED Requirements

### Requirement: Автономия живёт отдельно от ядра
Наблюдатель, триггеры, дедуп, тихие часы и сводка ДОЛЖНЫ находиться в `src/autonomy/` и не
импортировать ядро (`bot.mjs`). Ядро пользуется доменом только для чтения отчётов.

#### Scenario: Ядро занято
- GIVEN ядро выполняет длинную задачу
- WHEN таймер алертов срабатывает
- THEN рантайм автономии работает независимо
- AND пишет аудит и отправляет уведомление

### Requirement: Уведомления — через порт integrations
Отправка алертов ДОЛЖНА идти через клиент из `integrations`, а не собственным `fetch` в
домене.

#### Scenario: Telegram недоступен
- GIVEN клиент уведомлений возвращает ошибку
- WHEN алерт не отправлен
- THEN аудит фиксирует причину
- AND дедуп не считает его отправленным

### Requirement: Состояние — через storage
Дедуп, «стоп» и отложенные предупреждения ДОЛЖНЫ храниться в файлах состояния домена и
переживать перезапуск сервиса.

#### Scenario: Перезапуск
- GIVEN сервис перезапущен
- WHEN алерты проверяются снова
- THEN «стоп» и история отправок сохранены
- AND повторная отправка не происходит в окне дедупа

### Requirement: Пороги и отчёт доступны ядру
Отчёт `/observe` и состояние алертов ДОЛЖНЫ отдаваться через публичный API домена, чтобы
ядро не читало внутренние файлы само.

#### Scenario: Команда /observe
- GIVEN владелец спрашивает про наблюдения
- WHEN ядро обрабатывает команду
- THEN отчёт собирает домен
- AND ядро только отправляет текст
