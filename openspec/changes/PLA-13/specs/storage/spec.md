# Дельта для домена storage

## ADDED Requirements

### Requirement: Принятая задача записывается долговечно
Журнал задач ДОЛЖЕН обеспечивать долговечную запись принятой задачи: после успешного
ответа вызывающему код может быть уверен, что запись переживёт перезапуск процесса.
Обычная запись истории может оставаться отложенной, но принятие задачи, смена состояния и
финальный статус — нет.

#### Scenario: Долговечное принятие
- GIVEN задача принимается
- WHEN запись возвращает успех
- THEN данные записаны и подтверждены на диске
- AND повторный запуск процесса видит эту задачу

#### Scenario: Ошибка записи
- GIVEN диск недоступен или кончилось место
- WHEN журнал пытается сохранить принятую задачу
- THEN операция завершается ошибкой
- AND вызывающий код не получает успешного результата

### Requirement: Журнал переходов
Каждая запись задачи ДОЛЖНА хранить переходы состояния с временем и причиной. История
переходов не должна теряться при перезаписи журнала.

#### Scenario: Смена состояния
- GIVEN задача меняет состояние
- WHEN переход сохраняется
- THEN в записи появляется отметка времени, прежнее и новое состояние, причина
- AND после перезапуска история переходов доступна

### Requirement: Восстановление состояния после загрузки
Хранилище ДОЛЖНО предоставлять восстановление: задачи в очереди, незавершённые выполнения
и ожидание владельца. Загрузка не должна сама менять поведение без явного вызова
восстановления.

#### Scenario: Незавершённое выполнение
- GIVEN журнал содержит задачу в состоянии выполнения
- WHEN выполняется восстановление
- THEN задача помечается как прерванная
- AND сохраняются последние известные промежуточные данные

### Requirement: Ключи повторных запросов уникальны
Хранилище ДОЛЖНО хранить ключ повторного запроса вместе с задачей и находить задачу по
ключу после перезапуска. Один ключ не может соответствовать двум задачам.

#### Scenario: Повтор после перезапуска
- GIVEN задача с ключом сохранена
- WHEN процесс перезапускается и приходит тот же ключ
- THEN хранилище возвращает прежнюю задачу
- AND новая запись не создаётся

### Requirement: Журнал внешних действий
Хранилище ДОЛЖНО вести журнал внешних действий с состояниями «начато», «подтверждено»,
«неизвестно» и уметь возвращать незавершённые действия по задаче.

#### Scenario: Сбой между началом и подтверждением
- GIVEN действие записано как начатое
- AND подтверждение не записано
- WHEN задача восстанавливается
- THEN действие считается неизвестным
- AND повтор действия требует решения владельца

### Requirement: Совместимость схемы журнала
Хранилище ДОЛЖНО читать прежнюю версию журнала задач и переносить старые статусы в новые
состояния без потери записей.

#### Scenario: Журнал прежней версии
- GIVEN на диске журнал задач версии 1
- WHEN агент загружается после обновления
- THEN записи читаются и переносятся в новую схему
- AND задачи не теряются и не объявляются заново выполненными
