# PLA-42 / G1: почасовой подбор ready-заявок через устойчивую очередь

Основание: review G1. Был прямой `/v1/implement`; фонового детерминированного подбора
готовых заявок не было.

## Что меняется
- `request-poller`: раз в час читает ветки `req/*` spec-репозитория, проверяет
  manifest+approval+status, без LLM; отдаёт nextPollAt/lastError/lastFound.
- Готовая заявка ставится в существующую очередь (lease/cancel/journal), а не
  выполняется обходным путём.
- Ключ идемпотентности `implement:<REQ>:r<revision>`; явный retry — новая попытка.
- `/v1/poll` и `/v1/poll/status`; рабочая операция выполняется через очередь.
