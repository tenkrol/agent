# Изменение: корректность проверки таблиц и исследований

Основание: повторная проверка опубликованных исходников
(`agent-review-fixes-spec.md`, разделы 2–3). Исправления оформляются отдельным изменением;
закрытые PLA-14/16/17 остаются историей.

## Зачем
Проверка результата в двух местах даёт ложноположительный статус:

- при пересчёте таблицы игнорируется `ok: false`, проверяется только первый файл (и только
  первый лист через первый файл), а исключение порта превращается в «ошибок нет»;
- проверка исследования выполняется регулярками по словам «источники», «предположения»:
  фраза «Источники отсутствуют» может дать `passed`, а вердикт модели не имеет схемы.

Владелец получает «проверено», хотя формулы не пересчитаны или источники не подтверждены.

## Что меняется
- **verification/таблицы**: пересчёт каждого файла результата, явные статусы
  `passed/failed/unavailable`, сохранение обнаруженных ошибок в свидетельствах,
  различение «ошибок нет» и «пересчёт не подтверждён», имя проблемного файла в отчёте.
- **verification/исследования**: структурированный JSON-вердикт по независимым критериям
  (источники, связь выводов, предположения), проверка схемы; ключевые слова больше не
  считаются доказательством; при неразобранном вердикте — `unavailable`, общий итог не
  `passed`; ограничение «фактическая проверка содержимого источников не выполнялась»
  попадает в отчёт.
- **критерии**: у исследования появляется отдельный критерий «связь выводов с источниками».

## Чего не делаем
- Не меняем модель, лимиты и архитектуру; не добавляем внешний фактчекинг источников.
- Не пересчитываем и не перезаписываем файл таблицы: если исходный файл содержал ошибку,
  пересчёт не может «исправить» уже выданный результат.
- Не трогаем остальные пункты повторной проверки (вопросы, процедуры, бюджет исправления) —
  они пойдут отдельными изменениями.

## Как проверяем
- Тесты: недоступный/упавший/таймаут пересчёта → `unavailable`; второй повреждённый файл →
  общий итог не `passed` и имя файла в свидетельстве; ошибка формулы сохраняется при
  недоступном пересчёте; успешный пересчёт без ошибок → `passed`.
- Тесты исследования: JSON-схема, отказ по всем критериям, источники без связи, битый JSON,
  отсутствие поля → `unavailable`.
- Полный прогон тестов агента и живая проверка XLSX/исследования через контракт.
