# Дельта для домена verification

## MODIFIED Requirements

### Requirement: Минимальные проверки по типу результата
Домен ДОЛЖЕН применять минимальные проверки, соответствующие результату:

| Результат | Минимальная проверка |
|---|---|
| Документ | Файл открывается, содержит требуемые разделы; при значимых требованиях к оформлению проверяется отображение |
| Таблица | Каждый файл открывается, нужные данные присутствуют, применимые формулы пересчитаны и проверены |
| Изменение кода | Выполнены подходящие проверки; результат и ограничения зафиксированы |
| Исследование | Выводы связаны с источниками, предположения отделены от подтверждённых сведений |

#### Scenario: Второй файл повреждён
- GIVEN результат содержит две таблицы
- WHEN первая проходит проверку, а вторая не открывается
- THEN итог проверки не равен «пройдена»
- AND свидетельство называет проблемный файл

## ADDED Requirements

### Requirement: Пересчёт таблицы должен быть подтверждён
Критерий вычислений ДОЛЖЕН получать «пройден», только если пересчёт каждого табличного
файла подтверждён успешным результатом и в файле нет ошибок формул. Пустой массив ошибок
при неуспешном пересчёте не подтверждает вычисления.

#### Scenario: LibreOffice недоступен
- GIVEN таблица открывается и содержит данные
- WHEN пересчёт возвращает «не выполнено» и причину
- THEN критерий вычислений «недоступен»
- AND итог проверки не равен «пройдена»
- AND отчёт указывает, что формулы не пересчитаны

#### Scenario: Пересчёт выбросил исключение
- GIVEN таблица требует пересчёта
- WHEN порт пересчёта падает или превышает таймаут
- THEN ошибка не превращается в пустой успешный результат
- AND итог проверки не равен «пройдена»

#### Scenario: Ошибка формулы
- GIVEN при чтении обнаружена ошибка `#REF!`
- WHEN пересчёт недоступен
- THEN обнаруженная ошибка сохраняется в свидетельстве
- AND не заменяется утверждением «ошибок формул нет»

#### Scenario: Пересчёт исправил ошибку
- GIVEN исходный файл содержал ошибку формулы
- WHEN пересчёт стал успешным, но проверенная версия не сохранена и не выдана
- THEN критерий вычислений «провален»
- AND в свидетельстве есть исходная ошибка и пометка об отсутствии сохранённой версии

### Requirement: Вердикт исследования структурирован
Проверяющая модель ДОЛЖНА возвращать структурированный JSON-вердикт по независимым
критериям: наличие источников, связь выводов с источниками, отделение предположений.
Каждый критерий содержит статус и краткое обоснование. Ответ ДОЛЖЕН проходить проверку
схемы; ключевые слова в тексте ответа не являются доказательством.

#### Scenario: Все критерии отклонены
- GIVEN ответ содержит фразу «Источники отсутствуют»
- WHEN проверяющая модель отклоняет критерии
- THEN ни один критерий не получает «пройден» из-за ключевого слова
- AND итог не равен «пройдена»

#### Scenario: Источники есть, связь не установлена
- GIVEN в ответе есть список ссылок
- WHEN вердикт не подтверждает связь выводов с источниками
- THEN критерий связи не получает «пройден»
- AND общий итог не «пройдена»

#### Scenario: Вердикт не разобран
- GIVEN модель вернула некорректный JSON, неизвестный статус или пропустила поле
- WHEN вердикт обрабатывается
- THEN непроверенные критерии «недоступны»
- AND итог не равен «пройдена»

### Requirement: Границы проверки источников обозначены
Система ДОЛЖНА различать оценку структуры ответа и фактическую проверку содержимого
источников. Без чтения источников проверка не ДОЛЖНА представляться как фактчекинг.

#### Scenario: Доступен только текст ответа
- GIVEN проверяющая модель получила текст ответа без содержимого источников
- WHEN формируется отчёт
- THEN ограничение «фактическая проверка источников не выполнялась» указано явно
- AND итог не выдаётся за независимый фактчекинг
