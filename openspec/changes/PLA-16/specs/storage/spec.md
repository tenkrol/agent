# Дельта для домена storage

## ADDED Requirements

### Requirement: Хранение процедур с версиями
Хранилище ДОЛЖНО вести `procedures.json` с атомарной записью, версией схемы и историей
версий процедур вместе с их статусом (`draft`, `active`, `archived`).

#### Scenario: Сохранение версии
- GIVEN создаётся новая версия процедуры
- WHEN запись завершена
- THEN версия сохранена со своим статусом, прежние версии не изменены
- AND после перезапуска доступны все версии

#### Scenario: Битый файл
- GIVEN файл процедур повреждён
- WHEN хранилище загружается
- THEN копия повреждённого файла сохранена рядом
- AND агент стартует с пустым списком и пишет об этом в журнал

### Requirement: Версия схемы файла процедур проверяется
Хранилище ДОЛЖНО проверять версию схемы файла процедур и не принимать незнакомую версию
как валидную. Это отдельная проверка от версии самой процедуры.

#### Scenario: Файл будущей версии
- GIVEN файл содержит версию схемы новее, чем понимает код
- WHEN хранилище загружается
- THEN файл откладывается в копию
- AND данные не подменяются

### Requirement: Черновики и активные версии различаются
Хранилище ДОЛЖНО хранить статус каждой версии и не выдавать черновик как действующую
версию. `activeVersion` процедуры НЕ ДОЛЖЕН указывать на `draft`.

#### Scenario: Черновик в файле
- GIVEN в файле есть версия со статусом `draft`
- WHEN процедура загружается
- THEN она не считается активной
- AND `run` получает отказ с перечнем недостающих полей

#### Scenario: Активация
- GIVEN черновик заполнен
- WHEN версия активируется
- THEN статус меняется на `active`
- AND `activeVersion` указывает на неё

### Requirement: Срок и число версий ограничены
Хранилище ДОЛЖНО соблюдать `PROCEDURES_MAX_VERSIONS` и `PROCEDURES_RETENTION_DAYS`: удалять
старые архивные версии и удалённые процедуры по сроку, не теряя версию, на которую
ссылается задача.

#### Scenario: Старая задача
- GIVEN задача ссылается на версию процедуры
- WHEN наступает уборка старых версий
- THEN используемая задачами версия не удаляется
- AND снимок версии в задаче остаётся доступен

#### Scenario: Предел числа версий
- GIVEN у процедуры больше версий, чем `PROCEDURES_MAX_VERSIONS`
- WHEN выполняется уборка
- THEN удаляются самые старые архивные версии
- AND активная версия и версии, на которые ссылаются задачи, сохраняются
