# Спека домена execution

## ADDED Requirements

### Requirement: Задача изолирована
Запуск задачи ДОЛЖЕН идти через домен execution: DSH стартует в собственной cgroup с
лимитами из настроек (память, CPU, число процессов), таймаут обязателен.

#### Scenario: Тяжёлая задача
- GIVEN задача превышает лимит памяти
- WHEN DSH запускается
- THEN задача завершается ошибкой лимита, а сервис продолжает работать
- AND cgroup после завершения убирается

### Requirement: Бюджет проверяется до и учитывается после
Домен ДОЛЖЕН проверять потолок шагов и токенов до запуска и передавать фактический расход
в домен storage после, чтобы ядро не считало токены само.

#### Scenario: Задача упирается в шаги
- GIVEN задача достигла предела шагов
- WHEN исполнитель возвращает результат
- THEN домен сообщает об остановке по лимиту
- AND расход записан в журнал

### Requirement: Промпт собирается в домене
Текст задачи для исполнителя ДОЛЖЕН собираться одной функцией домена: вложения, память,
план, режим вариантов. Ядро не склеивает промпт вручную.

#### Scenario: Задача с вложением и памятью
- GIVEN у задачи есть файл и факты о владельце
- WHEN собирается промпт
- THEN в него попадают и файл, и память, и инструкции
- AND ограничение по длине соблюдается

### Requirement: Ответ разбирается в домене
Извлечение вопроса (`ВОПРОС:`), вариантов (`ВАРИАНТ N:`) и готового текста ДОЛЖНО происходить
в домене; ядро получает структурированный результат, а не ищет префиксы само.

#### Scenario: Агент задаёт вопрос
- GIVEN ответ исполнителя содержит `ВОПРОС:`
- WHEN домен разбирает ответ
- THEN ядро получает вопрос и признак «ждёт ответа»
- AND обычный текст вопроса не содержит

### Requirement: Быстрый слой решает сам
Решение «ответить одним вызовом модели или запускать исполнителя» ДОЛЖНО приниматься в
домене, с теми же правилами и лимитами, что и раньше.

#### Scenario: Короткий вопрос
- GIVEN короткий вопрос без файлов и интернета
- WHEN домен решает способ исполнения
- THEN выбирается быстрый слой
- AND результат помечается как быстрый

### Requirement: Рабочая папка задачи — только домен
Создание рабочей папки задачи, `AGENTS.md`, `outbox`, `inbox` ДОЛЖНО быть в домене; другие
домены не создают файлы задач по своим путям.

#### Scenario: Новая задача
- GIVEN начинается задача
- WHEN домен готовит рабочую папку
- THEN `AGENTS.md`, `outbox` и `inbox` создаются в одном месте
- AND другие домены используют готовые пути

## ADDED Requirements

### Requirement: Критерии попадают в промпт
Промпт задачи ДОЛЖЕН содержать проверяемые критерии результата, чтобы исполнитель знал,
что именно будет проверено, и не подменял требования.

#### Scenario: Задача с критериями
- GIVEN у задачи есть критерии формата и разделов
- WHEN собирается промпт
- THEN критерии перечислены в тексте задачи
- AND ограничение длины промпта соблюдается

### Requirement: Обратная связь после провала проверки
При повторной попытке ДОЛЖНЫ передаваться проваленные критерии и требование исправить
именно их, без расширения задачи.

#### Scenario: Исправление документа
- GIVEN проверка нашла отсутствующий раздел
- WHEN запускается повторная попытка
- THEN в промпт попадает, какой критерий провален
- AND просьба исправить только это

### Requirement: Порт проверок кода
Домен ДОЛЖЕН предоставлять порт запуска проверок кода (тесты, линтер, сборка) в cgroup с
таймаутом, возвращая команды, коды возврата и хвосты вывода. Порт принимает `root` —
рабочую папку задачи — и не запускает проверки с `cwd` вне неё. Набор разрешённых команд
ограничен allowlist (`VERIFY_CHECK_ALLOWLIST`); команда вне allowlist НЕ запускается и
возвращает «недоступно», произвольный запуск запрещён.

#### Scenario: Тесты прошли
- GIVEN критерий требует прогона тестов из allowlist
- WHEN порт запускает команду
- THEN возвращается код возврата и вывод
- AND процесс не выходит за лимиты cgroup и таймаут

#### Scenario: Команда вне allowlist
- GIVEN команда проверки не входит в allowlist
- WHEN порт вызывается
- THEN команда не запускается
- AND возвращается «недоступно (команда не разрешена)», а не «пройдено»

#### Scenario: Проверка не запускается
- GIVEN команда проверки отсутствует, allowlist пуст или окружение не позволяет запуск
- WHEN порт вызывается
- THEN возвращается «недоступно»
- AND это не превращается в успешную проверку

#### Scenario: Выход за рабочую папку
- GIVEN `cwd` проверки вне `root`
- WHEN порт вызывается
- THEN запуск отклоняется
- AND проверка получает статус «недоступно»
