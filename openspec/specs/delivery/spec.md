# Спека домена delivery

## ADDED Requirements

### Requirement: Как выглядит ответ — решает домен
Сборка текста ответа (заголовок, тело, диагностика, подпись, заметки) ДОЛЖНА происходить в
домене `delivery` из готовых данных. Ядро не склеивает текст ответа вручную.

#### Scenario: Обычная задача
- GIVEN задача завершилась успешно
- WHEN формируется ответ
- THEN домен собирает текст и подпись со стоимостью
- AND ядро передаёт только числа

### Requirement: Условия заголовка сохраняются
Заголовок ДОЛЖЕН различать отмену, превышение шагов, превышение бюджета, таймаут и код
ошибки ровно так же, как раньше.

#### Scenario: Лимит шагов
- GIVEN задача остановлена по лимиту шагов
- WHEN домен строит заголовок
- THEN в тексте есть причина и совет сузить задачу
- AND статус задачи не подменяется на «выполнена»

### Requirement: Длина ответа ограничена
Длинный ответ ДОЛЖЕН обрезаться до предела из настроек с пометкой об обрезке.

#### Scenario: Очень длинный ответ
- GIVEN ответ больше предела
- WHEN домен собирает текст
- THEN текст обрезан и помечен
- AND остальные части отчёта сохранены

### Requirement: Домен не зависит от других доменов
Сборка текста ДОЛЖНА использовать только переданные данные: числа, флаги и строку
стоимости. Импортов других доменов в `src/delivery/` быть не должно.

#### Scenario: Проверка границ
- GIVEN в домен добавляют импорт стоимости из `storage`
- WHEN запускается сторожевой тест
- THEN тест падает и указывает файл

## ADDED Requirements

### Requirement: Блок проверки в отчёте
Отчёт ДОЛЖЕН содержать результат проверки: что проверено, что не проверено и почему.
Результат с непроверенными обязательными критериями НЕ ДОЛЖЕН выглядеть как полностью
проверенный.

#### Scenario: Проверка пройдена
- GIVEN обязательные критерии выполнены
- WHEN собирается отчёт
- THEN есть строка «Проверка: …» с перечнем пройденного
- AND заголовок соответствует успешному завершению

#### Scenario: Проверка недоступна
- GIVEN проверку выполнить не удалось
- WHEN собирается отчёт
- THEN есть строка «Не проверено: …» с причиной
- AND заголовок не утверждает полную проверку

#### Scenario: Проверка отключена
- GIVEN ядро передаёт `verification.status = disabled` (`VERIFY=false`)
- WHEN собирается отчёт
- THEN есть явная строка «Проверка отключена (VERIFY=false)»
- AND результат не выглядит проверенным

#### Scenario: Проверка не требуется
- GIVEN ядро передаёт `verification.status = not_required`
- WHEN собирается отчёт
- THEN есть строка «Проверка не требуется для этого результата»
- AND это не подаётся как «не проверено»

### Requirement: Заголовок частичного результата
Отчёт о частичном результате ДОЛЖЕН явно отличаться от отчёта об успехе и называть
проваленные критерии.

#### Scenario: Частичный результат
- GIVEN задача завершена частично
- WHEN домен строит текст
- THEN заголовок говорит о частичном выполнении
- AND перечислены проваленные или непроверенные критерии

### Requirement: Проверка не подменяет состояния
Текст отчёта ДОЛЖЕН строиться из переданного состояния и результата проверки; домен
НЕ ДОЛЖЕН сам решать, выполнена задача или нет.

#### Scenario: Передан частичный результат
- GIVEN ядро передаёт статус «завершена частично» и результат проверки
- WHEN домен собирает текст
- THEN текст соответствует переданному статусу
- AND домен не пересчитывает проверки
