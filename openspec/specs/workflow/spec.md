# Спека домена workflow

Правила самого процесса разработки: как оформляются изменения, как проверяется структура,
где живут секреты и на каком языке пишутся спеки.

## ADDED Requirements

### Requirement: Изменение оформляется папкой change
Любое изменение поведения ДОЛЖНО иметь папку `openspec/changes/<ГГГГ-ММ-ДД>-<слаг>/`
с `proposal.md`, `tasks.md` и дельтой-спекой в `specs/<домен>/spec.md`.

#### Scenario: Новая возможность
- GIVEN в репозитории нет папки изменения для задачи
- WHEN агент или человек начинает менять поведение
- THEN сначала создаётся папка изменения со спекой
- AND код меняется только после одобрения спеки владельцем

#### Scenario: Правка без изменения поведения
- GIVEN изменение — опечатка или форматирование
- WHEN оно коммитится
- THEN в сообщении коммита стоит пометка «без change»
- AND папка изменения не создаётся

### Requirement: Структура проверяется автоматически
`bash tools/spec-check.sh` ДОЛЖЕН находить папки изменений без proposal, tasks или дельты,
имена не в формате `ГГГГ-ММ-ДД-<слаг>` и дельты без требований.

#### Scenario: Неполное изменение
- GIVEN в `changes/` лежит папка без `tasks.md`
- WHEN запускается `spec-check`
- THEN команда завершается с ненулевым кодом
- AND перечисляет, чего не хватает

### Requirement: Секреты не попадают в репозиторий
Значения ключей НЕ ДОЛЖНЫ попадать в репозиторий, в промпт задачи, в чат или в логи.

#### Scenario: Нужен ключ для работы
- GIVEN задаче нужен доступ к внешнему API
- WHEN составляется промпт
- THEN в промпте нет значений секретов
- AND ключ берётся из окружения процесса на сервере

### Requirement: Спеки и комментарии на русском
Требования, сценарии, документация и комментарии в коде пишутся по-русски, требования
формулируются через «ДОЛЖЕН» и сценарии GIVEN/WHEN/THEN.

#### Scenario: Новая спека
- GIVEN агент пишет дельту-спеку
- WHEN он формулирует требование
- THEN текст на русском, формат «ДОЛЖЕН» + сценарий GIVEN/WHEN/THEN
