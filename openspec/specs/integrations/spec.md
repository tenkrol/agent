# Спека домена integrations

## ADDED Requirements

### Requirement: Сеть живёт только в integrations
Сетевые вызовы (Bot API Telegram, Яндекс.Диск, HTTP-приём) ДОЛЖНЫ находиться в
`src/integrations/`. Остальные домены получают готовые порты и не вызывают сеть напрямую.

#### Scenario: Новый внешний сервис
- GIVEN понадобился новый внешний API
- WHEN выбирается место для кода
- THEN клиент живёт в `src/integrations/`, остальным доменам отдаётся порт
- AND сторожевой тест не находит сетевых вызовов вне домена

### Requirement: Порт отправки сообщений
Отправка и правка сообщений ДОЛЖНЫ идти через порт платформы (`createTelegramPlatform`),
а не через прямые вызовы клиента из доменов исполнения и доставки.

#### Scenario: Ответ задачи
- GIVEN задача завершилась
- WHEN результат нужно отправить
- THEN доставка вызывает порт платформы
- AND не знает адресов Bot API и формата запросов

### Requirement: Порт архива файлов
Выгрузка, публичные ссылки и чтение файлов архива ДОЛЖНЫ идти через порт Диска
(`YandexDisk`), а режим (REST или WebDAV) выбирается настройкой, не кодом домена.

#### Scenario: Файл уходит в архив
- GIVEN у задачи есть файлы на выход
- WHEN архив включён
- THEN порт Диска выгружает файл и возвращает путь
- AND домен доставки не знает, REST это или WebDAV

### Requirement: Ошибки внешних API не глотаются
Клиенты ДОЛЖНЫ возвращать ошибку с понятным текстом (класс ошибки и статус), чтобы
вызывающий домен мог решить, повторить или сообщить владельцу.

#### Scenario: Telegram недоступен
- GIVEN Bot API отвечает ошибкой
- WHEN порт отправляет сообщение
- THEN возвращается ошибка с кодом, а не тихий пропуск
- AND текст ошибки не раскрывает токен
