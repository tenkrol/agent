# Спека домена orchestration

## ADDED Requirements

### Requirement: Оркестратор — единственный владелец жизненного цикла
Принятая задача ДОЛЖНА выполняться через один оркестратор: исполнение, проверка и
исправление. Адаптер входа (Telegram, HTTP-мост, расписание) не ведёт второй цикл
исполнения или исправления.

#### Scenario: Задача из бота
- GIVEN корректный запрос по действующему контракту
- WHEN задача принята
- THEN она выполняется зарегистрированным исполнителем один раз
- AND результат возвращается в исходный маршрут прежним контрактом.

#### Scenario: Неизвестный исполнитель
- GIVEN запрошен исполнитель, которого нет в реестре
- WHEN оркестратор выбирает исполнителя
- THEN возвращается понятная ошибка
- AND тихая подмена другим исполнителем не происходит.

### Requirement: Общая отмена
У попытки ДОЛЖЕН быть один родительский сигнал отмены. Исполнение, проверка и
исправление получают его; после отмены новая стадия не начинается, а поздний ответ
проверки не меняет терминальный исход на успех.

#### Scenario: Отмена во время исправления
- GIVEN первичный запуск завершён, проверка потребовала исправления
- WHEN владелец отменяет задачу
- THEN активный процесс получает отмену
- AND новое исправление не начинается
- AND задача завершается как отменённая, а не успешная.

### Requirement: Остаточный бюджет
Бюджет попытки ДОЛЖЕН включать токены, шаги и время. Лимит процедуры может только
уменьшать глобальный потолок. Проверка и исправление получают остаток; расход неудачной
попытки учитывается; неизвестный расход отмечается явно и не открывает бесконечные
бесплатные исправления.

#### Scenario: Исправление не получает новый лимит
- GIVEN лимит 10000 токенов, первичный запуск потратил 7000, проверка 1000
- WHEN разрешено исправление
- THEN его доступный остаток не превышает 2000
- AND расход исправления входит в общий итог независимо от успеха.

#### Scenario: Бюджет исчерпан
- GIVEN после проверки доступного бюджета не осталось
- WHEN результат требует исправления
- THEN новый запуск не начинается
- AND причина завершения отражает лимит, а не успешную проверку.
