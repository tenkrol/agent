# Спека домена tools

## ADDED Requirements

### Requirement: Вложения разбирает домен
Определение типа вложения (фото, скан, документ, голос), извлечение текста и распознавание
ДОЛЖНЫ происходить в домене `tools`. Ядро передаёт файл и получает готовый текст или описание.

#### Scenario: Скан документа
- GIVEN пришёл скан страницы
- WHEN домен обрабатывает вложение
- THEN текст извлекается локальным OCR или vision
- AND ядро не выбирает провайдера само

### Requirement: Провайдеры получают HTTP-клиент портом
Сетевые провайдеры (vision, STT, TTS) ДОЛЖНЫ принимать HTTP-клиент (`fetchImpl`) и не
обращаться к глобальной сети напрямую.

#### Scenario: Проверка порта
- GIVEN домен загружается в тесте
- WHEN провайдер создаётся с подставным `fetchImpl`
- THEN запрос идёт через него
- AND сторожевой тест не находит прямого `fetch(` в домене

### Requirement: Локальные инструменты под контролем
Запуск локального OCR ДОЛЖЕН быть ограничен доменом `tools`; лимиты (размер, время, формат)
проверяются до запуска.

#### Scenario: Слишком большой файл
- GIVEN файл превышает лимит распознавания
- WHEN домен пытается его обработать
- THEN возвращается понятная ошибка
- AND процесс распознавания не запускается

### Requirement: Голос — в том же домене
Распознавание речи и синтез ответа ДОЛЖНЫ жить в домене; ядро получает готовый текст или
аудио и не знает, какой провайдер используется.

#### Scenario: Голосовое сообщение
- GIVEN пришло голосовое
- WHEN домен его расшифровывает
- THEN ядро получает текст задачи
- AND длинная запись честно помечается как нераспознанная

## ADDED Requirements

### Requirement: Инспекция документа
Домен ДОЛЖЕН предоставлять проверку документа: открывается ли файл, какой текст содержит,
какие разделы присутствуют. Для значимых требований к оформлению — рендер отображения
(страницы, изображение) для последующей проверки.

#### Scenario: Валидный документ
- GIVEN документ создан
- WHEN домен его инспектирует
- THEN файл открывается, текст и разделы доступны
- AND при требовании к оформлению доступен рендер

#### Scenario: Битый документ
- GIVEN файл повреждён
- WHEN домен его инспектирует
- THEN возвращается ошибка открытия
- AND проверка не считается пройденной

### Requirement: Инспекция и пересчёт таблицы
Домен ДОЛЖЕН предоставлять открытие таблицы, чтение листов и значений, список формул,
ошибки формул и пересчёт формул локальным офисным движком.

#### Scenario: Пересчёт формул
- GIVEN таблица содержит формулы
- WHEN домен пересчитывает её
- THEN возвращаются вычисленные значения
- AND ошибки формул перечислены отдельно

### Requirement: Проверки не расширяют прав
Инспекция, пересчёт и рендер ДОЛЖНЫ работать только с файлами рабочей папки задачи и в тех
же ограничениях, что и остальные инструменты домена. Порт получает `root` — корень задачи —
и разрешает запрошенный путь относительно него; выход за `root` (включая `..` и
символические ссылки наружу) отклоняется. Файл, создаваемый рендером, тоже остаётся внутри
`root`.

#### Scenario: Чужой путь
- GIVEN проверка просит файл вне рабочей папки
- WHEN домен обрабатывает запрос
- THEN запрос отклоняется
- AND файл не читается

#### Scenario: Обход через `..` или ссылку
- GIVEN путь формально начинается с `root`, но после разрешения выходит за его пределы
- WHEN домен проверяет путь
- THEN запрос отклоняется с ошибкой «вне рабочей папки»
- AND проверка получает статус «недоступна»

#### Scenario: Рендер пишет результат
- GIVEN требуется отображение документа
- WHEN рендер создаёт PDF/PNG
- THEN файл создаётся внутри `root`
- AND путь за его пределами отклоняется
