# Спека домена core

## ADDED Requirements

### Requirement: Ядро — только оркестрация
`src/core/` ДОЛЖЕН содержать приём сообщений, доступ владельца, маршрутизацию, очередь,
команды и сессии. Бизнес-правила (промпты, триггеры, формат ответа, расчёты) в ядре
находиться НЕ ДОЛЖНЫ — они живут в своих доменах.

#### Scenario: Новая команда
- GIVEN нужна новая команда
- WHEN определяется место для правила
- THEN правило живёт в домене, в `core` добавляется только вызов и ответ

### Requirement: Расписания — часть ядра
`schedule.mjs` ДОЛЖЕН находиться в `core`: он решает «когда запускать» и не знает, как
исполняется задача.

#### Scenario: Запуск по расписанию
- GIVEN наступило время задачи по cron
- WHEN ядро обрабатывает тик
- THEN задача ставится в очередь через домен исполнения
- AND поведение не отличается от запуска по сообщению

### Requirement: Задача принимается только после сохранения
Ядро ДОЛЖНО сохранять задачу до подтверждения её принятия. Подтверждение означает, что
поручение можно восстановить после перезапуска. Ошибка сохранения НЕ ДОЛЖНА приводить к
запуску выполнения или к успешному подтверждению.

#### Scenario: Ошибка сохранения
- GIVEN хранилище недоступно
- WHEN поступает поручение
- THEN система сообщает, что задача не принята
- AND не запускает выполнение
- AND не возвращает успешное подтверждение мосту

#### Scenario: Обычное принятие
- GIVEN хранилище доступно
- WHEN поступает поручение
- THEN запись задачи сохраняется на диск
- AND только после этого задача попадает в очередь и владелец получает идентификатор

### Requirement: Восстановление очереди
Очередь ДОЛЖНА восстанавливаться из постоянного журнала после перезапуска. Принятые
задачи сохраняют тот же идентификатор и порядок очереди.

#### Scenario: Перезапуск после принятия
- GIVEN задача принята и ожидает выполнения
- WHEN агент перезапускается
- THEN задача остаётся доступной под прежним идентификатором
- AND возвращается в очередь с сохранением порядка

#### Scenario: Перезапуск с несколькими задачами
- GIVEN три задачи приняты подряд и ещё не выполнялись
- WHEN агент перезапускается
- THEN все три восстанавливаются в исходном порядке
- AND выполняются по одной, как до перезапуска

### Requirement: Явные состояния выполнения
Задача ДОЛЖНА иметь одно из состояний: в очереди, выполняется, ожидает владельца,
проверяется, завершена, завершена частично, ошибка, отменена или прервана. Каждый переход
ДОЛЖЕН сохраняться с временем и причиной.

#### Scenario: Переход по ходу выполнения
- GIVEN задача принята
- WHEN она начинает выполняться и затем завершается
- THEN журнал содержит переходы `queued → running → done`
- AND у каждого перехода есть время и причина

#### Scenario: Недопустимый переход
- GIVEN задача уже завершена
- WHEN код пытается вернуть её в выполнение
- THEN переход отклоняется
- AND запись в журнал задач не подменяется

### Requirement: Прерванная задача не объявляется завершённой
Если после перезапуска обнаружено незавершённое выполнение, задача ДОЛЖНА быть помечена
как прерванная, доступные промежуточные результаты сохранены, а завершение — не объявлено.

#### Scenario: Процесс остановлен во время выполнения
- GIVEN задача выполнялась
- WHEN после перезапуска обнаружено незавершённое выполнение
- THEN задача отмечается как прерванная
- AND сохраняются доступные промежуточные результаты
- AND система не объявляет её завершённой

### Requirement: Продолжение с учётом выполненных действий
При продолжении задачи система ДОЛЖНА учитывать уже выполненные действия. Действия с
неизвестным исходом нельзя автоматически повторять, если повтор может создать внешний
эффект.

#### Scenario: Неизвестен результат отправки
- GIVEN перед сбоем выполнялась отправка сообщения
- AND подтверждение отправки не сохранилось
- WHEN задача продолжается
- THEN система проверяет доступное подтверждение
- OR сообщает владельцу о неопределённости до повторной отправки

#### Scenario: Продолжение прерванной задачи
- GIVEN задача помечена прерванной и неизвестных действий нет
- WHEN владелец запускает продолжение
- THEN система продолжает выполнение с сохранённым контекстом
- AND в отчёте видно, что было сделано до сбоя

### Requirement: Защита от повторной постановки
Повторная передача одного запроса с тем же ключом ДОЛЖНА возвращать существующую задачу.

#### Scenario: Потерян ответ моста
- GIVEN агент сохранил поручение
- AND ассистент не получил подтверждение
- WHEN ассистент повторяет тот же запрос
- THEN агент возвращает прежний идентификатор
- AND второе выполнение не создаётся

#### Scenario: Ключ без дедупликации
- GIVEN старый клиент не передаёт ключ запроса
- WHEN он повторяет запрос
- THEN создаётся новая задача
- AND в журнал пишется предупреждение об отсутствии защиты от дублей
